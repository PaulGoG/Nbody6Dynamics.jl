# Input File Reference

The inputs ship under `input_files/` in the package tree, one folder per purpose. `example_input(name)` returns the absolute path of one for a project outside the checkout (`example_input("engine/N1k_quick.inp")`; a bare name such as `example_input("N1k_quick.inp")` is looked up across the folders). Five kinds of file exist:

- **engine inputs** (`.inp`, under `engine/`) — Fortran NAMELIST inputs of single-cluster Nbody6++ runs whose initial conditions the engine generates itself, used through `simulation.input_file`;
- **single-cluster configurations** (`.toml`, under `clusters/`) — one cluster for the Julia generator, in the same schema as the merger configurations with `orbit_mode = "single"`; the science cases;
- **merger configurations** (`.toml`, under `mergers/` and `verification/`, and the merger TOMLs of `showcase/` and `gpu/`) — initial conditions for the Julia generator, used through `merger.config_file` or `run_merger_pipeline`;
- **pipeline configurations** (`*_pipeline.toml` under `showcase/` and `gpu/`) — complete configurations for `scripts/run_setup.jl`, with every path relative to their own folder;
- **sweep configurations** (`sweeps/`, `showcase/sweep.toml`) — a grid over a merger TOML for `scripts/run_sweep.jl`.

```
input_files/
├── engine/          # single-cluster engine inputs (engine-generated initial conditions)
├── clusters/        # single-cluster configurations of the generator: the science cases
├── mergers/         # merger initial-condition configurations
├── verification/    # the two targets of scripts/run_verif_suite.jl
├── sweeps/          # sweep configurations
├── showcase/        # five end-to-end cases (Showcase Cases)
└── gpu/             # CUDA-host validation and the probes above 5 × 10⁵ bodies
```

## Engine inputs

| File | Purpose |
|---|---|
| `engine/N1k_quick.inp` | 1k-particle smoke test; Plummer model, isolated, no binaries, TCRIT=5 NB, Level C |
| `engine/N5k_medium.inp` | 5k-particle medium test; Plummer model, isolated, no binaries, TCRIT=10 NB; the `single` target of the verification suite |
| `engine/N10k_long.inp` | 10k-body Plummer model, Z=0.001, point-mass tide at 13.3 kpc, no binaries, TCRIT=50 NB |
| `engine/N25k_production.inp` | 25k Plummer model; Z=0.001, 200 primordial binaries generated by the engine (`KZ(8) = 1`, log-flat semi-major axes from `&INBINPOP`), point-mass tide at 13.3 kpc, TCRIT=200 NB |
| `engine/N100k_production.inp` | 100k Plummer model; Z=0.001, 500 engine-generated primordial binaries, point-mass tide at 13.3 kpc, TCRIT=100 NB |

The initial conditions of these files are the engine's own (a Plummer model, `KZ(5) = 1`, with masses from the engine's mass function; `KZ(22) = 0`, or `1` where the engine also writes them to `dat.10` at start). Every file sets `QE = 1.0E-02`: with `KZ(2) = 1` the engine halts when the relative energy change over one adjustment interval exceeds `5 QE`, and these runs evolve stars (`KZ(19) = 3`), carry binaries, and mostly sit in a point-mass tidal field whose work the engine's energy check charges to the error, so a tolerance of the order of `1e-4` stops them on ordinary events (a KS termination halted the 1k smoke run at t = 3 of 5) while `1.0` would disable the check. At `1e-2` the check still catches an integration that goes wrong by 5 % per interval, which is what it is for.

Every file writes a restart dump at every adjustment (`KZ(2) = 1` with `NCOMM = 1`; the engine counts every dump call and writes one in `NCOMM`, the dump of an `END RUN`, of a stop request or of an energy halt included, so a larger `NCOMM` loses those). `simulation.checkpoint_keep` bounds the disk the dumps take. `TCRTP0` is the engine's termination time in Myr (the run ends at the earlier of `TCRIT` and `TCRTP0`); the files set it far above `TCRIT` in physical units, so `TCRIT` decides. The 1k and 5k files are isolated (`KZ(14) = 0`); the three larger ones carry the `&INXTRNL0` namelist of their point-mass field.

To use an `.inp` file, point `simulation.input_file` at it, relative to the directory of the configuration (from the root `config.toml` of a checkout):

```toml
[simulation]
run_test   = true
input_file = "input_files/engine/N25k_production.inp"
```

These go through the generator like a merger configuration (`merger.config_file`, or `run_merger_pipeline`): `orbit_mode = "single"` with `n_clusters = 1` samples one cluster, places it at the origin at rest, and writes `dat.10` with its `merger.inp` (`KZ(22) = 2`; pairs first, `KZ(8) = 2`).
```toml
[merger]
enabled     = true
config_file = "input_files/clusters/imbh_runaway.toml"
```

## Single-cluster configurations: the science cases

The four files of `clusters/` are science cases rather than tests: each sets up a cluster in which a specific dynamical process dominates, with the parameters that process needs. They are shipped as starting points, not as validated results: each has been run through its first time units on the CPU build, none to its end time. Every file samples a Kroupa IMF between 0.08 and 150 M☉, evolves the stars at level `C` [Kamlah2022](@cite) and uses the energy tolerance `qe = 0.01` of the shipped engine inputs; the end times quoted in N-body units are rounded from the generator's time unit `T*` of the sampled system (the exact values are in each run's `merger_summary.txt`). Every file requests a restart dump at every adjustment (`checkpoint = true`), so a multi-day run can resume after an interruption; set `simulation.checkpoint_keep` to bound the disk.

### `gc_bh_subsystem.toml` — globular cluster with a black-hole subsystem

Metal-poor globular clusters retain a population of stellar-mass black holes that segregates to the core and forms a dynamically decoupled subsystem: it delays core collapse by acting as a central energy source, hardens black-hole binaries in three-body encounters and produces mergers, and is depleted by dynamical ejection; once it is exhausted the cluster undergoes a late core collapse [BreenHeggie2013](@cite), and the mass-loss rate of the cluster rises with the black-hole mass fraction [GielesGnedin2023](@cite). Palomar 5 is the observed archetype [Gieles2021](@cite), and the DRAGON-II models of up to 10⁶ stars are the reference direct simulations [ArcaSedda2024](@cite). Set-up: 100 000 stars, King `W0 = 6`, `r_h = 3` pc, `Z = 2×10⁻⁴`, a binary fraction of 0.05 (by systems) with log-flat semi-major axes between 0.01 and 100 AU, point-mass galaxy of 10¹¹ M☉ at 8 kpc on a circular orbit, 2 Gyr (about 6200 N-body time units): the formation of the subsystem and its early depletion, not the 12 Gyr life of the cluster. Expected: mass segregation of the black holes within about 100 Myr, binary hardening and ejected mergers, gradual depletion, tidal stripping. The engine's point-mass field (`KZ(14) = 2`) charges the tidal work to its energy check (see Cluster Mergers, "Escapers").

### `imbh_runaway.toml` — runaway stellar collisions in a dense young cluster

In dense young clusters (`r_h` of 0.1–0.5 pc) the most massive stars sink to the core within a Myr and collide repeatedly, building a very massive star that can collapse into an intermediate-mass black hole [Rizzuto2021](@cite), [ArcaSedda2023](@cite), [Vergara2025](@cite). Set-up: 100 000 stars, King `W0 = 9`, `r_h = 0.5` pc, `Z = 0.001`, no primordial binaries, isolated, 20 Myr (about 900 N-body time units, the runaway phase). Expected: mass segregation of the O and B stars within 1–2 Myr, runaway mergers in the core, a very massive star and its collapse at a few Myr, exchange encounters that form an IMBH binary, hypervelocity ejections. Collisions between the components of a regularised pair are the engine's sticky-sphere mergers; the relativistic terms of `KZ(27)` are not switched on.

### `young_massive_binaries.toml` — young massive cluster with a high binary fraction

More than seventy per cent of massive O stars are born in binaries [Sana2012](@cite); in a dense young cluster these drive mass transfer, stripped-envelope supernovae, exchange encounters and the dynamical ejection of runaway stars, as the R136 analogues of Banerjee et al. show [Banerjee2012](@cite) and the two waves of runaways observed from R136 require [Stoop2024](@cite). Set-up: 50 000 stars with a binary fraction of 0.5 by systems, King `W0 = 6`, `r_h = 1` pc, `Z = 0.02`, isolated, 50 Myr (about 580 N-body time units). The pairs follow the generator's Kroupa (1995) birth period distribution with thermal eccentricities and random pairing; the period and mass-ratio distributions of massive binaries measured by Sana et al. are not among the generator's samplers, so the massive stars are paired like the rest. Expected: early supernovae ejecting neutron stars, binary disruptions and runaway OB stars, blue stragglers from mass transfer, double compact objects within about 30 Myr, a diverse escaper population.

### `open_cluster_tails.toml` — tidal tails of an open cluster

Clusters in a tidal field lose stars through the Lagrange points and develop tails whose morphology, with its epicyclic overdensities, records the orbit and the mass-loss history [Kupper2010](@cite); the Hyades tails are observed over 800 pc [Jerabkova2021](@cite), and the asymmetry between the leading and the trailing tail is a current test of the dynamics [Kroupa2022](@cite). Set-up: 2500 stars with a binary fraction of 0.5 by systems (about 1.5×10³ M☉), Plummer model, `r_h = 2.6` pc, `Z = 0.02`, point-mass galaxy of 10¹¹ M☉ at 8.5 kpc on a circular orbit (a circular speed of 225 km s⁻¹ at the solar radius), 650 Myr (about 430 N-body time units); `KZ(23) = 0` keeps the escapers, so the tails stay in the integration and `esc.11` is not written. Expected: stripping from the start, preferential loss of low-mass stars, tails of several hundred parsecs by the end. The point-mass field is the linearised tide of a circular orbit; a cluster on its measured orbit in a Galactic potential (`kz14 = 5`) is the next step from this file.

### Removed: the Population III case

An earlier version shipped a Population III cluster at `Z = 10⁻⁸`. The engine refuses it: with stellar evolution on, `ZMET` outside 10⁻⁴–0.03 stops the run before the first step (`data.F`), the range of the stellar-evolution fits [Hurley2000](@cite). Such clusters need the tracks of the models that simulate them [Wu2026](@cite), which this engine does not carry.

## Single-cluster `.inp` format (Fortran NAMELIST)

An `.inp` file is a sequence of NAMELIST blocks, each starting with `&BLOCKNAME` and ending with `/`, read in the order expected by `nbody6.F → start.F`:

| Block | Purpose |
|---|---|
| `&INNBODY6` | Run control: `KSTART` (1 = new run), `TCOMP` (CPU-time limit, s), `TCRTP0` (termination time in Myr; the run ends at the earlier of `TCRIT` and `TCRTP0`) |
| `&ININPUT` | Core physics: `N`, `NRAND` (seed), `NNBOPT`, timestep accuracies `ETAI`/`ETAR`, output intervals `DTADJ`/`DELTAT`, end time `TCRIT`, physical scales `RBAR`/`ZMBAR`, the `KZ(1:50)` option array, tolerances, and the stellar-evolution `Level` (`'C'` = [Kamlah2022](@cite), recommended) |
| `&INSSE` / `&INBSE` / `&INCOLL` | SSE/BSE/collision overrides (usually empty — Level defaults apply) |
| `&INDATA` | IMF (`ALPHAS`, `BODY1`, `BODYN`), binaries (`NBIN0`), metallicity `ZMET`, `DTPLOT` (sev.83 interval) |
| `&INSETUP` | External-IC placeholder block |
| `&INSCALE` | Initial virial ratio `Q`, rotation, tidal radius override |
| `&INXTRNL0` | External tidal field (only read when `KZ(14) > 0`) |
| `&INBINPOP` / `&INHIPOP` | Primordial binary / hierarchy populations (when `NBIN0`/`NHI0` > 0) |

KZ flags most relevant to this project: `KZ(2)` restart dumps `comm.2` at every adjustment (1; the dump of a termination is also subject to `NCOMM`), `KZ(3)` conf.3 snapshot output, `KZ(7)=3` Lagrangian radii (`lagr.7`), `KZ(8)` primordial binaries (1 = generated by the engine from `&INBINPOP`; 2 = the first `2·NBIN0` bodies of `dat.10` are the pairs, which needs `KZ(22) ≥ 2`), `KZ(12)=1` HR diagnostics (`sev.83_*`), `KZ(14)` tidal field (0 = isolated, 2 = point-mass galaxy, which reads `&INXTRNL0`), `KZ(19)=3` stellar evolution, `KZ(22)` initial conditions (0 = internal model, 1 = internal model written to `dat.10`, 2 = read `dat.10` in NB units, 10 = `dat.10` in astrophysical units), `KZ(23)` escaper removal (`esc.11`; 0 keeps every star), `KZ(46)` HDF5 output (produces `snap.40_*.h5part` — **not readable** by this package; keep conf.3 output enabled).

For the full option catalogue see the Nbody6++ manual (Khalisi & Spurzem, Heidelberg, unpublished), the code papers [Spurzem1999](@cite), [NitadoriAarseth2012](@cite) and [Wang2015](@cite), the stellar-evolution levels of [Kamlah2022](@cite), and the method review of [SpurzemKamlah2023](@cite).

## Merger TOML schema

`load_merger_config` accepts **two interchangeable schemas** for each `[merger.clusterN]` table: the flat form and the structured form. Both may appear in the same file (but not mixed within one cluster table).

### Top-level `[merger]` keys

| Key | Type | Default | Description |
|---|---|---|---|
| `n_clusters` | Int | `2` | Number of `[merger.clusterN]` tables to read (N = 1…n_clusters, all required) |
| `orbit_mode` | String | `"kepler"` | `"kepler"` (exactly 2 clusters, placement auto-computed), `"explicit"` (≥ 2 clusters, per-cluster `position`/`velocity` required), `"single"` (exactly 1 cluster at the origin, at rest; `position`/`velocity` refused, `truncate_jacobi` and `[merger.orbit]` ignored) or `"complex"` (a cluster complex from `[merger.complex]`, below; `n_clusters` and `[merger.clusterN]` refused, `[merger.orbit]` ignored) |
| `seed` | Int | *absent* | RNG seed; see [Seed semantics](@ref) |
| `seed_streams` | String | `"shared"` | `"shared"`: every cluster and its pairs are drawn from one `MersenneTwister(seed)` stream; `"per_cluster"`: cluster `i` is sampled and its pairs expanded from its own stream seeded by `(seed, i)`, so its realisation depends neither on the other clusters nor on the orbit. One of `"shared"`, `"per_cluster"`; with an external `rng` passed to `generate_merger_ic` the external stream is used for every cluster (warned) |
| `virial_max_n` | Int | `200000` | Largest N, per cluster and for the combined system, for which the exact O(N²) potential is evaluated (virialisation of each cluster, combined virial ratio). A cluster above it is refused at load, naming the key; raise the value deliberately for large initial conditions. The pair sum is threaded and costs ≈ N²/2 evaluations: 11 s at N = 2×10⁵ on twelve threads, quadratic from there |

### `[merger.orbit]` (Kepler mode only)

| Key | Type | Default | Description |
|---|---|---|---|
| `apocentre` | Float | `15.0` | Apocentre separation [pc]; > 0 |
| `apocentre_rh` | Float | `0.0` | Apocentre separation in units of the input half-mass radius `r_h,1` of cluster 1; > 0 when given |
| `pericentre` | Float | `0.0` | Pericentre separation [pc]; the apocentre is `r_p (1 + e) / (1 − e)`; > 0 when given |
| `pericentre_rh` | Float | `0.0` | Pericentre separation in units of `r_h,1`; > 0 when given |
| `eccentricity` | Float | `0.7` | Orbital eccentricity, `0 ≤ e < 1` |
| `orbit_normal` | [Float] | `[0, 0, -1]` | Direction of the orbital angular momentum of the pair; three finite components, non-zero norm |
| `apocentre_angle` | Float | `0.0` | Rotation of the apocentre direction about `orbit_normal` [degrees]; finite |

The size of the orbit is given by exactly one of `apocentre`, `apocentre_rh`, `pericentre`, `pericentre_rh`; two or more in the same table are refused, none falls back to `apocentre = 15.0`. The clusters start at apocentre. The orbital angular momentum of the pair is along `orbit_normal`; the default `[0, 0, −1]` is the orbit of earlier versions, in the x–y plane with cluster 2 on +x at apocentre. For another normal `n`, the apocentre direction is the projection of x̂ onto the plane normal to `n` (of ŷ when `n` is along x̂), rotated by `apocentre_angle` about `n`.

`merger_ic.toml` records the configured keys, the resolved apocentre (`apocentre_resolved`) and the derived orbit quantities: semi-major axis, pericentre (in pc and `r_h,1`), period, orbital energy and angular momentum, `j_orb = √(p / r_h,1)` (the specific orbital angular momentum in units of `√(G M r_h,1)`, `p` the semi-latus rectum), the pericentre speed over the velocity dispersion of cluster 1, the spin parameter λ of [Peebles (1969)](https://doi.org/10.1086/149876) of the orbital angular momentum, and the Roche-lobe radii at apocentre after [Eggleton (1983)](https://doi.org/10.1086/160960) with the filling factor of each cluster's outermost kept system.

In `"explicit"` mode this section is ignored (a warning is emitted if present).

### `[merger.output]`

| Key | Type | Default | Description |
|---|---|---|---|
| `format` | String | `"nbody"` | `dat.10` in N-body units, `KZ(22)=2` (only supported value) |
| `truncate_jacobi` | Bool | `true` | Truncate each cluster at its nearest-neighbour Jacobi radius before combining; ignored in single mode |
| `truncate_radius_rh` | Float | `0.0` | With `truncate_jacobi = true` and a positive value, every cluster is truncated at `truncate_radius_rh` times its own input half-mass radius instead of the orbit-dependent Jacobi radius (kepler and explicit modes); `0` keeps the Jacobi radius; finite, ≥ 0. The mass removed per cluster is recorded as `mass_truncated` [M☉] in `merger_ic.toml` |
| `output_dir` | String | `""` | Output directory; a relative path resolves against the TOML's own directory. Empty leaves the choice to the caller: `run_merger_pipeline` creates `runs/merger_<timestamp>/` under the working directory, and the main pipeline always writes into `runs/merger_.../output/` |
| `tcrit` | Float | `100.0` | Simulation end time (NB units for `"nbody"`) |
| `dtadj` | Float | `1.0` | ADJUST diagnostic interval |
| `deltat` | Float | `1.0` | Snapshot (conf.3) interval |
| `tcrit_myr`, `dtadj_myr`, `deltat_myr` | Float | `0.0` | The same three in Myr; a positive value replaces the NB one and is converted at generation with the realised time unit `T*` (both forms of one key: error). `dtadj`, `deltat` and the stellar `dtplot` are written as the nearest dyadic rational with an exact decimal expansion (`engine_interval`, change below 0.4 %), because the engine counts their decimal digits with a loop that never terminates on other values |

### `[merger.nbody6]`

Integration parameters written to `merger.inp`, in N-body units of the combined system (length unit `RBAR`, mass unit `M_total`). A zero for a derivable key means "take the preset's value or rule at generation time": with `r_h` the smallest member half-mass radius in those units, `N_min` the smallest post-truncation membership, and `ρ̂` the central density contrast of that member's profile, the `"engine"` rules are those of the engine's own example inputs and of its `adjust.F` evaluated for the member cluster instead of the whole configuration, and the `"baseline"` rules are those of the calibration programme: η_I = 0.01 (the manual's value), η_R = 0.02 (the benchmarks of [NitadoriAarseth2012](@cite)), 100 neighbours (the middle of the manual's range), `RMIN` three times the 90° deflection scale `4 r_h/N` of the smallest member (the manual's example and the 10⁶-body run of [Wang2015](@cite), which both found the engine's automatic re-derivation too small), and `DTMIN` 0.4 of the Aarseth close-encounter step at that `RMIN`. Explicit nonzero keys override the preset in both cases.

| Key | `"engine"` | `"baseline"` |
|---|---|---|
| `etai`, `etar`, `etau` | 0.02, 0.02, 0.1 | 0.01, 0.02, 0.1 |
| `nnbopt` | `clamp(round(√N_total), 20, 300)` | 100 |
| `rs0` | `min(2 r_h (2 NNBOPT / N_min)^{1/3}, r_h)` | the same |
| `rmin` | `4 r_h / (N_min ρ̂^{1/3})` | `12 r_h / N_min` |
| `dtmin` | `0.04 √(ETAI/0.02) √(RMIN³ N_total)` | `0.016 √(ETAI/0.02) √(RMIN³ N_total)` |
| `kz16`, `KZ(17)`, `KZ(32)` | free | must be 0 (no automatic adjustment of the integration parameters) |

| Key | Type | Default | Description |
|---|---|---|---|
| `preset` | String | `"engine"` | Source of every zero entry below; one of `"engine"`, `"baseline"` (table above; the former name `"campaign"` is read as `"baseline"` with a deprecation warning) |
| `binary_physics` | String | `"inherited"` | Few-body and binary options of the input; one of `"inherited"`, `"full"` (table below; the former name `"campaign"` is read as `"full"` with a deprecation warning); `"full"` requires `stellar.kz19 ≥ 3` |
| `qe` | Float | `2.0e-4` | Energy-error tolerance per adjustment interval (`QE`); must be > 0 |
| `etai` | Float | `0.0` | Irregular time-step factor; `0` = preset value; must be ≥ 0 |
| `etar` | Float | `0.0` | Regular time-step factor; `0` = preset value; must be ≥ 0 |
| `nnbopt` | Int | `0` | Target neighbour number; `0` = preset rule; must be ≥ 0 |
| `rs0` | Float | `0.0` | Initial neighbour-sphere radius; `0` = `2 r_h (2 NNBOPT / N_min)^{1/3}` capped at `r_h` (the factor 2 follows the engine's example inputs; the engine regrows an empty sphere itself, so the value sets start-up cost, not correctness); must be ≥ 0 and, when set, no larger than the smallest member half-mass radius |
| `rmin` | Float | `0.0` | KS regularisation distance; `0` = preset rule; must be ≥ 0 |
| `dtmin` | Float | `0.0` | KS time-step threshold; `0` = preset rule, evaluated with the resolved `etai`; must be ≥ 0 |
| `kz16` | Int | `0` | `KZ(16)`: the engine's re-derivation of `RMIN`, `DTMIN`, and `ECLOSE` from its global scale radius and core density every `DTADJ`; `0` keeps the written values (recommended for multi-cluster systems, required by the campaign preset); one of 0, 1, 2, 3 |
| `etau` | Float | `0.0` | Regularised time-step factor; `0` = preset value; must be ≥ 0 |
| `eclose` | Float | `1.0` | Binding energy per unit mass of a hard binary; must be > 0 |
| `gmin` | Float | `1.0e-6` | Relative perturbation for unperturbed KS motion; `0 < gmin < gmax` |
| `gmax` | Float | `0.01` | Termination parameter for soft KS binaries; `> gmin` |

Keep `1`: with a larger value the dump of an `END RUN`, of a stop request or of an energy halt is written only when the count happens to fit |

The generator logs the size of one dump and of all of them. `false` (`KZ(2) = −1`) leaves the dump at the end of the run or at a stop request as the only one |

Runs with stellar evolution need the relaxed tolerance `qe ≈ 1e-2`: supernova kicks change the energy budget between adjustments, and the default tolerance halts the run.

`binary_physics` selects the few-body and binary options. `"inherited"` keeps the block the generator has always written: no chain and no stable hierarchies (`KZ(15) = 0`), no gravitational-wave decay of compact pairs (`KZ(27) = 0`), no binary event files. `"full"` writes the complete set adopted for the binary programme, with the Level defaults of `&INSSE`, `&INBSE` and `&INCOLL` (zero recoil of GW mergers, `fctorcl = 0.5`); it needs an engine from the fork tag `v2026.07.6`, the default pin: the decay of compact KS pairs follows the Peters equations from `v2026.07-campaign.5` on, and earlier builds end the run at the first binary–binary chain (a run-time FORMAT error) and can end a run with an unrestartable dump inside a chain.

| 9, 10 | 0, 0 | 3, 2 | binary event files (`binev.17`, `degen.4`, `hbin.39`); `NEW`/`END KSREG` lines |
| 15, 30 | 0, 1 | 2, 2 | chain regularisation and stable hierarchies, with their begin and end records |

| 27, 28 | 0, 0 | 3, 1 | Peters decay of compact KS pairs with sequential tides; GW braking of the inner compact binaries of hierarchies |

`[merger.nbody6.kz]` holds explicit `KZ(i) = v` overrides with string keys `"1"`–`"50"` and integer values, applied after every named option and after the `binary_physics` set (an override of an index that also has a named key, 8, 14, 16, or 19, warns). `KZ(18) ≥ 2` is refused: it runs the engine's primordial-triple generator on the `dat.10` pairs, and the generator writes no triples. `KZ(46) > 0`, the per-binary custom output (several GB per N-body time unit at 6×10⁵ bodies), warns:

```toml
[merger.nbody6.kz]
"8" = 2      # primordial binaries from dat.10
"47" = 1
```

The resolved values appear in `merger_summary.txt` and in `merger_ic.toml` (`[nbody6]`, `[stellar]`), next to the combined virial ratio `Q = T/|W|`, the ratio `RBAR/r_hm,min`, the crossing times of the configuration and of the smallest member in N-body units and Myr, and the N-body time unit `T*` (`[meta]`). Generation warns when `Q < 0.3` (cold-collapse regime: global infall dominates and the engine's global diagnostics are meaningless until the remnant forms), when `RBAR/r_hm,min > 5` (members unresolved by the single-centre diagnostics), and when `deltat` exceeds the smallest member crossing time (member dynamics undersampled), and refuses an `rs0` wider than the smallest member.

### `[merger.tidal]`

| Key | Type | Default | Description |
|---|---|---|---|
| `kz14` | Int | `0` | `KZ(14)`: `0` isolated; `1` standard solar-neighbourhood linearised tide (no parameters); `2` point-mass galaxy on a circular orbit; `5` MWPotential2014 with the configuration on a galactocentric orbit. `3` and `4` are refused (see below); one of 0, 1, 2, 5 |
| `gmg` | Float | `0.0` | Galaxy mass [M☉] for `kz14 = 2`; must be > 0 |

Under `kz14 = 1, 2` the engine integrates in the frame that rotates with the circular Galactic orbit, Ω = Ω ẑ (Ω = A − B = 26.4 km/s/kpc with the engine's Oort constants for `kz14 = 1`, V_G/R_G for `kz14 = 2`), and takes the `dat.10` velocities as velocities in that frame. With the default `velocity_frame = "rotating"` the clusters are non-rotating and a Kepler pair orbit is a Kepler orbit in the rotating frame; `"inertial"` makes both inertial. An orbit with `orbit_normal = [0, 0, 1]` is prograde with respect to the Galactic rotation, `[0, 0, -1]` retrograde, `[1, 0, 0]` polar. A Kepler pair is refused when its apocentre reaches the pair Jacobi radius (G M/(4A(A − B)))^{1/3} (≈ 1.41 (M/M☉)^{1/3} pc for `kz14 = 1`; (G M/(3Ω²))^{1/3} for `kz14 = 2`) and warned above half of it; `merger_ic.toml` records the ratio (`orbit.apocentre_over_jacobi_pair`) and Ω (`tidal.omega_kms_pc`).

Options `3` (point mass + Miyamoto–Nagai disk + logarithmic halo + bulge) and `4` (Plummer potential) are refused: on those paths the engine rescales every velocity to the `&INSCALE` virial ratio including the external potential (`xtrnl0.F`), which destroys the prescribed orbital kinematics of a multi-cluster configuration. The `&INSCALE` tidal radius stays `0` so the engine derives it from the field with the generator's `RBAR`; a non-zero value would override `RBAR`. In a tidal field the engine removes escapers on the distance criterion alone, and because it does not evaluate the tidal potential energy its energy check measures the tidal work: a tidal configuration requires `merger.nbody6.qe ≥ 0.01` (see the merger documentation).

The `&INDATA` mass bounds `BODY1`/`BODYN` are written from the clusters' IMF specifications (inert under `KZ(22) = 2`, where masses come from `dat.10`); `ALPHAS` is inert for the same reason. `NBIN0` is the number of primordial pairs (see `[merger.clusterN.binaries]`); `NHI0 = 0`, no hierarchies are generated.

### Flat cluster form

Fully annotated example (Kepler mode):

```toml
[merger]
n_clusters = 2
orbit_mode = "kepler"       # 2 clusters placed at apocentre automatically
seed       = 42             # optional; omit for a random seed

[merger.cluster1]
model      = "king"         # density profile: "king" or "plummer"
N          = 5000           # bodies to sample
W0         = 6.0            # King central potential (ignored for "plummer", with a warning)
rbar       = 2.0            # target half-mass radius [pc]
imf        = "kroupa"       # "kroupa", "kroupa_rescaled", or "equal"
bodyn      = 0.08           # lower IMF bound [M☉]
body1      = 100.0          # upper IMF bound [M☉]
mass_total = 5e4            # optional — see IMF resolution below

[merger.cluster2]
model      = "king"
N          = 5000
W0         = 6.0
rbar       = 2.0
imf        = "kroupa"
bodyn      = 0.08
body1      = 100.0
mass_total = 5e4

[merger.orbit]
apocentre    = 12.0         # [pc]
eccentricity = 0.6

[merger.output]
format          = "nbody"
truncate_jacobi = true
tcrit           = 10.0
dtadj           = 0.5
deltat          = 0.5
```

**IMF resolution in the flat form:**

- `imf = "kroupa"` **without** `mass_total` → natural Kroupa sampling in `[bodyn, body1]`; the total mass is an *output* (the sum of the samples)
- `imf = "kroupa"` **with** `mass_total` → rescaled Kroupa: samples are uniformly rescaled so the sum equals `mass_total`. The rescale factor `mass_total / (N ⟨m⟩)` is checked when the file is loaded: outside ×[0.7, 1.4] the loader warns, outside ×[0.5, 2] it refuses the configuration, because the bodies would no longer be stars while stellar evolution is always active in merger runs. Choose `N` and `mass_total` consistent with the IMF mean (about 0.58 M☉ over 0.08–100 M☉), drop `mass_total`, or use `imf = "equal"` for a collisionless super-particle model
- `imf = "kroupa_rescaled"` → same as above but explicit (documents intent; the same bounds apply); requires `mass_total`
- `imf = "equal"` → all bodies get mass `mass_total / N`; requires `mass_total`

A cluster table from `[merger.cluster2]` on may set its size by density instead of `rbar`:

| Key | Type | Default | Description |
|---|---|---|---|
| `density_ratio` | Float | *absent* | Mean density inside the half-mass radius of this cluster over that of cluster 1; derives `rbar = rbar_1 ((M / M_1) / density_ratio)^{1/3}` with the expected masses of the two IMF specifications. Finite, > 0; refused in `[merger.cluster1]` and together with `rbar` in the same table |

In `"explicit"` orbit mode each cluster table additionally requires:

```toml
position = [x, y, z]        # centre-of-mass position [pc]
velocity = [vx, vy, vz]     # centre-of-mass velocity [km/s]
```

In `"single"` orbit mode (`n_clusters = 1`) neither key is allowed: the cluster is placed at the origin, at rest, and `[merger.orbit]` is ignored.

### Structured cluster form (preferred for new configs)

Profile and IMF become inline TOML tables with a `type` discriminator:

```toml
[merger]
n_clusters = 2
orbit_mode = "kepler"
seed       = 42

[merger.cluster1]
N       = 1500
rbar    = 1.0                                        # half-mass radius [pc]
profile = { type = "king", W0 = 6.0 }                # or { type = "plummer" }
imf     = { type = "kroupa", bounds = [0.08, 100.0] }

[merger.cluster2]
N       = 1500
rbar    = 1.0
profile = { type = "plummer" }
# rescaled Kroupa: explicit target mass (super-particle mode)
imf     = { type = "kroupa_rescaled", bounds = [0.08, 100.0], target_mass = 1.5e4 }
# equal-mass alternative:
# imf   = { type = "equal", particle_mass = 10.0 }   # or target_mass (→ /N)

[merger.orbit]
apocentre    = 12.0
eccentricity = 0.6

[merger.output]
format          = "nbody"
truncate_jacobi = true
tcrit           = 10.0
```

Accepted table keys:

- `profile`: `type = "king"` (+ `W0`, default 6.0) or `type = "plummer"`
- `imf`: `type = "kroupa" | "kroupa_rescaled" | "equal"`; mass bounds either as `bounds = [lo, hi]` or as separate `bodyn`/`body1` keys (defaults 0.08 / 100.0); `kroupa_rescaled` requires `target_mass`; `equal` requires `particle_mass` **or** `target_mass` (divided by `N`)

The metadata file `merger_ic.toml` written next to `dat.10` stores cluster specs in this structured form, and the same parser reads it back — see `load_merger_ic_result`.

### `[merger.clusterN.binaries]` — primordial binaries

| Key | Type | Default | Description |
|---|---|---|---|
| `fraction` | Float | `0.0` | Binary fraction by systems, `N_b / (N_s + N_b)`; `0 ≤ fraction < 1` |
| `pairing` | String | `"random"` | `"random"`: both components drawn from the IMF, the more massive is the primary; `"uniform_q"`: the secondary's mass is `q m₁` with `q` uniform in `[q_min, 1]` (it replaces the drawn mass of the partner star) |
| `period` | String | `"kroupa1995"` | `"kroupa1995"`: the [Kroupa1995](@cite) birth period distribution `f(log P) ∝ (log P − 1)/(45 + (log P − 1)²)`, `1 ≤ log(P/d) ≤ 8.43`, converted to a semi-major axis with Kepler's third law; `"loguniform"`: semi-major axis log-uniform in `[a_min, a_max]` |
| `a_min`, `a_max` | Float | `0.01`, `100.0` | Semi-major axis bounds [AU] for `"loguniform"`; `0 < a_min < a_max` |
| `q_min` | Float | `0.1` | Lower mass-ratio bound for `"uniform_q"`; `0 < q_min < 1` |
| `eccentricity` | String | `"thermal"` | `"thermal"` (`f(e) = 2e`) or `"circular"` |

The density sampler places *systems* (a pair by its centre of mass), which are virialised and truncated as such; each pair is then expanded into two bodies on a Keplerian orbit with a random phase and orientation. The engine reads primordial pairs as bodies `2i − 1, 2i` for `i ≤ NBIN0`, so the pairs of all clusters are written first, cluster by cluster, followed by every cluster's singles; `NBIN0` and `KZ(8) = 2` are set in `merger.inp`, and a cluster's members are then two contiguous blocks recorded in `merger_ic.toml` (`cluster_blocks`) and recoverable from `merger_summary.txt` (`binaries: N` per cluster). The summary also reports the hard fraction of each cluster's pairs (`G m₁ m₂ / 2a > ⟨m⟩ σ²` of the cluster's systems). Binary-rich runs carry a larger energy error per adjustment interval (regularised pairs, chains): the two-cluster demo with 20 % binaries reached 4×10⁻³ over its first time unit, so set `merger.nbody6.qe` accordingly (10⁻³ to 10⁻²) or the engine halts at the first adjustment that exceeds the default 2×10⁻⁴.

### `[merger.clusterN.segregation]` — primordial mass segregation

| Key | Type | Default | Description |
|---|---|---|---|
| `method` | String | `"none"` | `"none"`: unsegregated sampling; `"bdk08"`: the scheme of Baumgardt, De Marchi & Kroupa (2008) |
| `degree` | Float | `0.0` | Degree of segregation `S`, `0 ≤ S ≤ 1`; `0` random assignment, `1` complete ordering |

With `method = "bdk08"` the generator follows Appendix A of [Baumgardt, De Marchi & Kroupa (2008)](https://doi.org/10.1086/590488). It samples `N′ = max(N, ⌈N ⟨m⟩/m_min⌉)` phase-space points of the unsegregated Plummer or King model and ranks them by specific energy, most bound first. The systems, sorted by mass in descending order, are permuted by the slot order of McLuster ([Kupper2011](@cite), Eq. A1, [DOI 10.1111/j.1365-2966.2011.19412.x](https://doi.org/10.1111/j.1365-2966.2011.19412.x)): the `i`-th most massive takes the free slot of rank `⌊(N − i + 1)(1 − X^{1−S})⌋`, `X` uniform. In that order each system takes one point from its own energy slice of `N′ m/M` points. Every system thus draws from the model's own phase-space distribution, so the mass-density profile and the virial equilibrium of the model are preserved, and the half-mass rescaling and virialisation that follow are unchanged. The scheme acts on system masses: a primordial pair is placed as its centre of mass before it is expanded. Complex members inherit the table of `[merger.complex.member]`. `rank_masses_by_energy!` of the static models is a different scheme: it permutes masses over fixed positions for the estimator calibration and changes the mass-density profile.

### `[merger.complex]` — cluster complexes

With `orbit_mode = "complex"` the generator builds a complex of member clusters from distribution parameters instead of per-cluster tables. Masses in M☉, lengths in pc, speeds in km s⁻¹.

| Key | Type | Default | Description |
|---|---|---|---|
| `n_members` | Int | `0` | Number of members; ≥ 2 when > 0 |
| `mass_total` | Float | `0.0` | Target total mass [M☉]; > 0 when used |
| `mass_function` | String | `"equal"` | `"equal"` (needs `n_members` and `mass_total`, every member `mass_total / n_members`) or `"power_law"` (exactly one of `n_members`, `mass_total`) |
| `beta` | Float | `2.0` | Slope of dN/dM ∝ M^−β; finite (`"power_law"`) |
| `mass_lo`, `mass_hi` | Float | `100.0`, `1.0e4` | Mass bounds [M☉]; 0 < `mass_lo` < `mass_hi` (`"power_law"`) |
| `size_mass` | String | `"constant"` | Size–mass relation: `"constant"`, `"marks_kroupa"`, `"frost"`, `"dobbs"` |
| `rh` | Float | `1.0` | Half-mass radius for `"constant"` [pc]; > 0 |
| `size_scatter_dex` | Float | `0.0` | Log-normal scatter of r_h [dex]; ≥ 0 |
| `centres` | String | `"uniform_sphere"` | Centre distribution: `"uniform_sphere"`, `"plummer"`, `"fractal"`, `"filament"` |
| `radius` | Float | `5.0` | Sphere radius, Plummer scale a, or fractal radius [pc]; > 0 |
| `plummer_cutoff` | Float | `5.0` | Plummer truncation in units of a; > 1 |
| `fractal_dimension` | Float | `1.6` | Box-fractal dimension D; 1 ≤ D ≤ 3 |
| `filament_length` | Float | `20.0` | Filament length [pc]; > 0 |
| `filament_width` | Float | `1.0` | Gaussian transverse σ of the filament [pc]; > 0 |
| `virial_ratio` | Float | `0.5` | Target Q_cc = T/\|W\| of the member centres; ≥ 0 |
| `rotation_fraction` | Float | `0.0` | T_rot/T of a solid-body rotation about +z; 0 ≤ f < 1; must be 0 when `virial_ratio = 0` |
| `softening` | Float | `0.0` | Plummer softening ε of the point-mass energy [pc]; `0` = the mean member r_h; ≥ 0 |
| `member_n_min` | Int | `50` | Smallest allowed member star count; ≥ 2 |
| `imf_partition` | String | `"member"` | `"member"` (each member samples the template IMF) or `"global"` (one star list for the whole complex, partitioned into the members) |
| `control` | String | `"none"` | `"none"`, `"monolithic"` (C-E) or `"cold"` (C-cold): write the energy-matched monolithic control instead of the complex; needs `imf_partition = "global"` |

The member template `[merger.complex.member]` is a cluster table in the flat or structured form above (`model`, `W0`, `imf`, `bodyn`, `body1`, `profile`, `binaries`). `N`, `rbar`, `position`, `velocity` and `density_ratio` are refused, since the complex sets them, and so is an IMF with a target mass (`mass_total`, `target_mass`): the member masses come from the mass function. Member i has `Nᵢ = round(Mᵢ / ⟨m⟩)` stars, ⟨m⟩ the mean stellar mass of the template IMF; a member below `member_n_min` stops the generation with an error naming it.

```toml
[merger]
orbit_mode = "complex"
seed = 65

[merger.complex]
mass_function = "power_law"
mass_total = 2.0e4
beta = 2.0
mass_lo = 300.0
mass_hi = 3000.0
size_mass = "marks_kroupa"
centres = "fractal"
radius = 5.0
virial_ratio = 0.3

[merger.complex.member]
model = "plummer"
imf = "kroupa"
bodyn = 0.08
body1 = 100.0
```

A power-law mass function is sampled by the inverse CDF, `M = (lo^(1−β) + u (hi^(1−β) − lo^(1−β)))^(1/(1−β))` (`M = lo (hi/lo)^u` for β = 1), either `n_members` times or until the running sum reaches `mass_total`, the last draw kept. The size–mass relations are `r_h = 0.10 pc (M/M☉)^0.13` after [Marks & Kroupa (2012, Eq. 7)](https://doi.org/10.1051/0004-6361/201118231), `r_h = (2.365/8) pc (M/10⁴ M☉)^0.18` after the FROST-CLUSTERS models of [Rantala, Naab & Lahén (2024)](https://doi.org/10.1093/mnras/stae1413) (0.45 pc at 10⁵ M☉), and `r_h = 2.26 pc (M/10⁴ M☉)^0.27` after [Dobbs et al. (2022)](https://doi.org/10.1093/mnras/stac2474), each multiplied by `10^(size_scatter_dex g)` with `g` standard normal.

The centres follow one of four distributions. `"uniform_sphere"` fills a sphere of radius `radius` uniformly. `"plummer"` draws a Plummer sphere of scale `a = radius` truncated at `plummer_cutoff a`, with the speeds of the isotropic Plummer distribution function by the rejection method of Aarseth, Hénon & Wielen (1974, A&A 37, 183). `"fractal"` is the box fractal of [Goodwin & Whitworth (2004)](https://doi.org/10.1051/0004-6361:20031529): each parent cube spawns eight children, each of which survives as a parent of the next generation with probability 2^(D − 3) and inherits its parent's velocity plus a random component that shrinks with generation; `n` of the parents of the first generation with enough of them inside the unit sphere are kept and scaled to `radius`. `"filament"` spreads the centres uniformly along x over `filament_length` with Gaussian transverse offsets of σ = `filament_width`. The uniform sphere and the filament start from Gaussian random velocities.

The velocity field is scaled after the members are sampled, with their realised masses: centres and velocities are shifted to the mass-weighted mean, the potential energy `W = −Σ_{i<j} G mᵢ mⱼ / √(|rᵢ − rⱼ|² + ε²)` of the members as softened point masses is evaluated, and the velocities, stripped of their mass-weighted projection on the solid-body field `ẑ × r`, are rescaled so that `T = virial_ratio |W|`, with the fraction `rotation_fraction` of `T` in rotation about +z. `virial_ratio = 0` is a cold start with the centres at rest. The members are then assembled as in explicit mode (truncation included) with their own random streams: the complex draws its masses, radii and centres from the stream `(seed, 0)`, member i is sampled from `(seed, i)`.

`merger_ic.toml` records one `cluster<i>` table per member and a `[complex]` table with every key above; its subtable `[complex.realised]` holds the realised `n_members`, `mass_total`, `virial_ratio`, `e_total` [M☉ km² s⁻²], `l_total` [M☉ pc km s⁻¹], `rotation_fraction`, `softening` and the spin parameter λ = |L| √|E| / (G M^{5/2}) of [Peebles (1969)](https://doi.org/10.1086/149876) of the member centres. `merger_summary.txt` reports the same under `Complex:`.

With `imf_partition = "global"` the stars are not drawn member by member. After the member masses Mᵢ, one star list is drawn from the template IMF in batches of `max(1000, ⌈1.1 ΣMᵢ / ⟨m⟩⌉)` until its sum reaches ΣMᵢ, shuffled, and dealt out in order: member i takes stars until its mass reaches or exceeds Mᵢ, the last member until the running total reaches ΣMᵢ, and the rest of the list is dropped. A member's star count is the size of its share, its radius follows from its realised mass, and its `cluster<i>` table records the share as `imf.type = "explicit"` with `n`, `mass_total`, `mass_min` and `mass_max`.

The two controls answer whether the substructure of a complex matters at fixed stellar content and energy. Both are built from the same seed as the complex they are paired with: the complex is generated first (nothing is written) and its total energy E and virial ratio Q = T/|W| are evaluated over all stars, pairs expanded. A single Plummer cluster of the same star list, with the template's binaries, is then sampled and virialised at r_h = 1 pc from the stream `(seed, 1)` and rescaled about its centre of mass, positions by s and velocities by k. `control = "monolithic"` (C-E) keeps the cluster in virial equilibrium and matches the total energy, `s = E_c / E`, `k = 1/√s`; `control = "cold"` (C-cold) matches both E and the global Q of the complex, `|W| = |E| / (1 − Q)`, `T = Q |W|`, with `s = |W_c| / |W|` and `k = √(T / T_c)`. The scale factors are taken from the energies of the sampled systems, so with primordial binaries the realised all-star energy departs from the target by the pairs' internal energy. The control is written as a single cluster at the origin, at rest, in the output directory; `merger_ic.toml` keeps `orbit_mode = "complex"` and the `[complex]` table, and adds a `[control]` table with `kind`, `e_target` and `q_target` from the complex, the realised all-star `e_realised` [M☉ km² s⁻²] and `q_realised`, `r_h_pc`, `n_stars` and `mass_total`. A control needs the complex to be bound and its star count within `merger.virial_max_n`.

### Seed semantics

- `seed` **omitted** → a random seed is drawn at generation time (`0` is an ordinary seed). The IC is still reproducible after the fact: the effective seed is recorded in `merger_ic.toml` (`meta.seed`)
- `seed = n` (nonzero) → deterministic sampling with `MersenneTwister(n)`
- The effective seed also feeds the `NRAND` parameter of the generated `merger.inp`, so the Nbody6++ run inherits it
- If a caller passes an explicit `rng` to `generate_merger_ic`, sampling is **not** reproducible from the recorded seed; the metadata records this honestly via `meta.external_rng = true` (the seed still feeds `NRAND`)
- `meta.seed_streams` records the stream layout

Reproducible orbit grids: with `seed_streams = "per_cluster"` and either `truncate_jacobi = false` or `truncate_radius_rh > 0`, the progenitors of a two-cluster grid over apocentre, pericentre, eccentricity or orientation are identical at a fixed seed, body for body in their own centre-of-mass frames, so differences between grid points come from the orbit alone. With the shared stream, or with the orbit-dependent Jacobi truncation, each grid point draws or keeps a different realisation.

## `verif_triorbit.toml` — Lagrange-equilibrium triangle

Three equal-mass clusters (`m = 900` M☉ each: 1500 equal bodies of 0.6 M☉, so the equilibrium is exact and no massive star evolves within the run) on an equilateral triangle at radius `r = 6` pc from the centre of mass, given tangential (counter-clockwise) velocities so the configuration rotates rigidly as a bound Lagrange solution instead of falling inward.

For three equal masses `m` on an equilateral triangle of circumradius `r`, the net force on each body points at the centre with magnitude `G m² / (√3 r²)`; setting this equal to `m ω² r` gives the equilibrium angular velocity

```math
\omega^2 = \frac{G m}{\sqrt{3}\, r^3},
\qquad
\mathbf{v}_i = \omega\, (-y_i,\ x_i,\ 0).
```

With `G = 4.30091×10⁻³ pc (km s⁻¹)² M☉⁻¹`, `m = 900 M☉`, `r = 6 pc`: `ω ≈ 0.1017 km s⁻¹ pc⁻¹` and `|v| = ω r ≈ 0.6103 km s⁻¹` per cluster — exactly the `velocity` entries in the file.

Expected behaviour: the three cluster COMs trace a slowly rotating triangle while each cluster relaxes internally. This verifies the COM-trajectory tracking and the per-cluster virial diagnostic (`per_cluster_virial`) for *separated, stable* clusters; the config's equilibrium condition is also asserted in the test suite.

With stellar evolution active (the Level C defaults), BSE mass loss drives a slow symmetric adiabatic expansion of the triangle: all three separations grow together, by about a factor two over 20 NB. The pairwise distances must stay equal — asymmetric growth, or a shrinking triangle, indicates broken equilibrium velocities.

## The GPU-host and verification cases

### `verif_3d5cluster.toml`

Five clusters of 800 bodies placed well out of the z = 0 plane, which exercises the xz- and yz-projection panels and the three-dimensional COM tracking. The inward radial velocities are mild, so the clusters interact over `tcrit` without falling together completely.

### `gpu/merger_50k.toml`

Two equal King clusters of 25 000 stars on an eccentric orbit, the case of the hardware validation runs. The CUDA build is faster than the AVX build at every N measured, from N ≈ 2×10⁴ upwards, and the gain grows with N as the regular force scales as N²; the figures are in the manual, section Validated hardware.

### `gpu/gpu_pipeline.toml`

Clones and builds the engine with CUDA into its own tree — CPU and GPU objects differ — and runs `merger_50k.toml` on the first device. The host needs `nvcc` (CUDA ≥ 12.8 for the RTX 50 series, ≥ 11.8 for H100/H200), `nvidia-smi`, `gfortran`, `gcc`/`g++`, `make` and `git`.

### `gpu/cpu_pipeline.toml`

Clones and builds the AVX engine without CUDA into the default tree on the same host and runs the same merger as `gpu_pipeline.toml`, so the two runs and `bench/gpu_scaling.jl` are comparable binary against binary.

### `gpu/merger_600k.toml` and `gpu/single_600k.toml`

The probes above 5 × 10⁵ bodies. The merger is the case of `merger_50k.toml` at twelve times the membership: two King clusters of 300 000 stars, `W0 = 6`, half-mass radius 2 pc, Kroupa masses between 0.08 and 100 M☉, released at a 10 pc apocentre with `e = 0.5`; Jacobi truncation leaves 575 080 bodies, the combined half-mass radius is 5.3 pc and the N-body time unit 0.32 Myr. The single cluster has the same structure with 600 000 stars at rest (`n_clusters = 1`, single mode, no truncation; unit 0.07 Myr). Both are integrated for two time units with adjustments every 0.25 and outputs every 0.5, enough for the engine's cost per time unit to be measured well past start-up while the CPU reference stays within a few hours on a workstation. Both raise `virial_max_n` to 10⁶, since the generator otherwise refuses to virialise a cluster above 2 × 10⁵ stars; the pair sum takes about three minutes per case on twelve threads.

### `gpu/gpu_merger_600k.toml`, `gpu/cpu_merger_600k.toml`, `gpu/gpu_single_600k.toml`, `gpu/cpu_single_600k.toml`

The pipeline configurations of the two probes on the CUDA and the AVX binary: device 0, eight host threads, a start-up watchdog of one hour (the initial force and neighbour lists of 6 × 10⁵ bodies take minutes on the host), post-processing and figures on. Their install phase is off; they use the trees that `gpu_pipeline.toml` and `cpu_pipeline.toml` build. `postprocess.pair_sum_max_n = 100000` keeps the snapshot integrals, remnant and per-cluster diagnostics off at this size (skipped with a warning) and the binaries are compared on the engine time recorded in `RUN_INFO.toml`.
