Nbody6Dynamics.run_pipeline — Function
run_pipeline(cfg::Nbody6Config; base_dir = cfg.config_dir, run_id = "") -> Dict{Symbol,Any}

Top-level orchestrator that runs the full pipeline (or any subset) based on the config flags. This is the single entry point for config-driven workflows.

Pipeline phases (controlled by config flags)

PhaseControlled byNotes
Install/Buildinstall.enabledClone + compile Nbody6++
Simulationsimulation.run_testRun the N-body integration
Post-processpostprocess.enabledRead output data + sanity checks
Plotsvisualization.enabledGenerate static plots + GIF animations

Post-process–only mode

To run only post-processing and plotting on existing output (from this project or an external source), set in config.toml:

[simulation]
run_test = false          # skip simulation

[postprocess]
enabled   = true
data_dir  = "/path/to/output"   # point at any dir with Nbody6++ files

Then call:

cfg = load_config("config.toml")
results = run_pipeline(cfg)

If data_dir is empty but run_test = false, the most recent run in runs/ is post-processed.

run_id fixes the run directory name (<runs_dir>/<run_id>); when empty, generate_run_id derives it from simulation.run_id_prefix and the time.

base_dir is the project directory: every relative path of the configuration (install.install_dir, simulation.input_file, simulation.runs_dir, postprocess.data_dir, merger.config_file) resolves against it. It defaults to cfg.config_dir, the directory of the file load_config read, so julia scripts/run_setup.jl path/to/config.toml keeps its engine and its runs next to that file, never inside the package.

A simulation phase that ends on a stop request (simulation.wall_budget, or a signal) ends the pipeline there, with an empty result and no completion stamp; resume_pipeline continues it.

Returns

A Dict{Symbol,Any} with keys :snapshots, :diagnostics, :lagr, :escapers, :stellar_evo, :binary_evo, :stellar_census, :remnant (present only when corresponding data exists). Returns an empty dict if post-processing is disabled.

Nbody6Dynamics.resume_pipeline — Function
resume_pipeline(run_dir; base_dir = nothing) -> Dict{Symbol,Any}

Continue the pipeline of an interrupted run from the configuration frozen in run_dir: one more engine segment through resume_run, and, once the run has reached its end time, the post-processing and figure phases with the completion stamp. The call can be repeated: a run that is still short of its end time returns an empty result and waits for the next call, and a run whose pipeline has finished is left alone, so one queue job per segment needs no knowledge of how many segments the run takes.

Nbody6Dynamics.run_gpu_validation — Function
run_gpu_validation(; base_dir = pwd(), stages = [:suite, :gpu, :cpu, :bench],
                   bench_n = [20000, 50000, 100000], bench_threads = [4, 8],
                   bench_gpu_lists = nothing, bench_tcrit = 0.25,
                   dry_run = false, stop_on_failure = false) -> String

Run the acceptance sequence of a CUDA host and collect everything under <base_dir>/runs/gpu_validation_<machine>_<timestamp>/, <machine> being the hostname with compact CPU and GPU tags so that machines sharing a hostname stay distinguishable: HOST_INFO.toml (hardware fingerprint with the GPU query, compute capabilities, CUDA path and nvcc release, gcc, gfortran and glibc versions, the host compilers nvcc can be offered and the verdict of the host-compiler probe, Julia, package commit), one <stage>.log per stage, the benchmark CSV, the RUN_INFO.toml and telemetry.csv of every benchmark run, and VALIDATION.toml (command, status, exit code and duration per stage, the run directories the pipelines created). Stages, in order:

  • :suite — the test suite with NBODY6_GPU_TESTS=1 (CUDA build in a temporary tree, N = 1000 on one device, then on two when present);
  • :gpu — input_files/gpu/gpu_pipeline.toml: CUDA build into backend/Nbody6PPGPU-beijing-gpu and the 2 × 25 000-star merger on device 0;
  • :cpu — input_files/gpu/cpu_pipeline.toml: the AVX reference build and the same merger;
  • :bench — bench/gpu_scaling.jl over bench_n × bench_threads × bench_gpu_lists (default [[0]], plus [0, 1] when two devices are visible) for bench_tcrit N-body time units; needs both binaries;
  • :gpu_merger_600k, :gpu_single_600k, :cpu_merger_600k, :cpu_single_600k — the probes above 5×10⁵ bodies, input_files/gpu/<stage>.toml, each on the tree its binary needs; not in the default list.

The probe stages and the benchmark are launched with JULIA_NUM_THREADS set to auto unless the environment sets it, because their initial-condition generation is a threaded pair sum.

Each stage is a separate Julia process whose output is echoed and written to its log with terminal escape sequences removed; a failing stage is recorded and the later stages still run unless stop_on_failure is set. VALIDATION.toml is rewritten after every stage, so an interrupted sequence leaves a readable record.

A stage's verdict rests on its artefacts as well as its exit code: a :gpu, :cpu or probe stage that exits zero without leaving a run directory marked [pipeline] completed is recorded incomplete with the reason, because the run summary is written when the engine exits and a process killed during post-processing or plotting would otherwise pass. Every pipeline stage is launched with a run ID the driver assigns (--run-id, recorded as run_ids in VALIDATION.toml), so the directory that carries the verdict is identified by name and a concurrent run elsewhere under runs/ cannot be mistaken for it. A stage killed by one of retry_signals is run again, up to max_retries times, when it is listed in retry_stages. A retried pipeline stage starts from a clean run directory; the crashed attempt's directory is kept as runs/<run_id>.attempt<k>.signal<N> beside its log. The defaults retry the test suite once after a crash signal (SIGILL, SIGABRT, SIGBUS, SIGSEGV — a compiler crash during JIT is an upstream fault, not a verdict on the package) and nothing else: a pipeline stage is hours of work that is not repeated unasked, and SIGKILL or SIGTERM come from an operator, the out-of-memory killer or a session teardown, which a rerun would only meet again. Every retried signal is recorded with the stage.

With stop_on_failure = true the run is a gated chain: once a stage ends failed or incomplete, every later stage is recorded skipped with the reason after failed stage :<stage> and not run; and when the stage list holds a stage that needs nvcc (the suite, the CUDA build, the CUDA probes) while the host-compiler probe did not pass, every stage is skipped before anything runs, with the probe's verdict as the reason. A dry run plans the commands regardless.

With dry_run = true the host record and the planned commands are written and nothing is executed. Returns the validation directory.

Example

dir = run_gpu_validation(; stages = [:suite, :gpu])
TOML.parsefile(joinpath(dir, "VALIDATION.toml"))["results"]["suite"]["status"]

Nbody6Dynamics.postprocess — Function
postprocess(cfg::Nbody6Config; run_dir = "", base_dir = cfg.config_dir) -> Dict{Symbol,Any}

Run all enabled post-processing steps and return collected results.

Data directory resolution (in priority order):

  1. run_dir keyword — run_dir/output/ (from a simulation run)
  2. cfg.postprocess.data_dir — explicit external directory from config.toml, resolved against base_dir when relative
  3. Falls back to the most recent run under base_dir/<runs_dir>/ (via _find_latest_run); errors if none exists.

base_dir defaults to the configuration's config_dir (the directory of the file it was loaded from).

Besides the readers, the derived data products are computed here: the class census (:stellar_census), the integrals of motion of every snapshot (:integrals, SnapshotIntegrals, with postprocess.snapshot_integrals, including the Jacobi integral when the stdout capture echoes a linearised tidal field) and, for a merger run — one whose output holds a merger_summary.txt and at least two snapshots — the remnant diagnostics (:remnant, a RemnantDiagnostics), which reuse the integrals' bound sets. Both need an O(N²) pair sum per snapshot and run only while no snapshot holds more than postprocess.pair_sum_max_n stars. From the stdout capture the stamped event lines (:engine_events, EngineEvent) and the energy-jump localisation (:energy_events, EnergyEventAnalysis, with postprocess.energy_events) follow; with the integrals, the escapers and the counters of postprocess.events_file (:event_counters, EventCounters) the mass budget (:mass_budget, MassBudgetRow, with postprocess.mass_budget). Under a linearised tidal field (tidal_mode :linearised) the engine's DE is not an error measure and no interval is flagged.

Nbody6Dynamics.generate_plots — Function
generate_plots(results::Dict{Symbol,Any}, vis::VisualizationConfig;
               sim_dir::AbstractString = "", animations::Bool = true,
               pair_sum_max_n::Integer = PostprocessConfig().pair_sum_max_n,
               bound::NamedTuple = (;))

Generate all available plots (and, when animations = true, GIF animations) from post-processing results, saving into vis.output_dir. sim_dir names the directory holding the raw simulation output; when given, it is searched for merger_summary.txt to produce the merger-specific figures (inter-cluster separation, per-cluster virial ratio).

pair_sum_max_n bounds the merger figures built on O(N²) pair sums, the per-cluster virial ratio and structure, the bound-member density and velocity-dispersion profiles and the remnant figures: they are drawn only when no snapshot holds more particles than this, with a warning otherwise; the inter-cluster separation is drawn regardless. The bound-set selection behind the binary figures' hard/soft scale obeys the same limit, above which the scale is taken over every system. The default is that of PostprocessConfig, and the Nbody6Config method passes cfg.postprocess.pair_sum_max_n. bound holds the keywords max_passes and min_members of the bound-set selections (bound_set); the Nbody6Config method passes postprocess.bound_max_passes and postprocess.bound_min_members.

This is the single plot dispatcher — both the config-driven pipeline (via the Nbody6Config method) and postprocess_external route through it.

Nbody6Dynamics.load_config — Function
load_config(path::AbstractString) -> Nbody6Config

Parse a TOML configuration file and return a fully-typed Nbody6Config. Missing sections or keys fall back to defaults defined in the @kwdef structs; keys the configuration schema does not define are rejected, so a typo cannot pass silently. The parsed configuration is validated fail-fast by _validate: enumerated choices, numerical bounds, and required non-empty fields raise an ArgumentError naming the offending section.key before any pipeline phase starts. The directory of path is recorded as config_dir: relative paths in the configuration resolve against it, and it is the default base_dir of the entry points, so a project directory holding a config.toml receives its backend/ and runs/ there, wherever the package is installed.

Nbody6Dynamics.restart_simulation — Function
restart_simulation(run_dir; tcrit_extra, dump = nothing, tcrtp0 = nothing,
                   base_dir = nothing) -> String

Continue a finished or interrupted run from one of the engine's COMMON dumps for tcrit_extra further N-body time units. The chosen dump (default: the latest comm.[12]_<t> in output/) is copied to output/comm.1, which is what KSTART = 2 reads, as a working copy that is removed when the engine exits. A restart from a dump older than the last moves what was written after it to output/discarded/segment_<k>/, as resume_run does; that is the call for continuing a run to its original end time. A restart input is written from the run's original input file; the engine runs in the same output directory with stdout and stderr appended, so out1000, lagr.7, esc.11, and the time-stamped snapshot and stellar-evolution files continue. RUN_INFO.toml gains one entry in its segments list per launch and the telemetry of each segment goes to its own CSV. The frozen config.toml of the run carries absolute paths, so the engine tree is found without a base_dir; one may still be given to override it. Returns run_dir.

Nbody6Dynamics.resume_run — Function
resume_run(run_dir; base_dir = nothing) -> String

Continue an interrupted run to the end time of its original input. The call is idempotent: a completed run is left as it is, and a run that was stopped at its wall budget, killed, or ended by an engine error gets one more segment, started from the last complete restart dump.

The dump is the last one the engine reported in its stdout whose file is complete, at the exact time of that report. If the interrupted segment wrote anything after that dump (it was killed, not stopped), that part is moved to output/discarded/segment_<k>/ before the launch: the tail of the stdout capture, the later records of lagr.7, global.30, esc.11 and event.35, and the later snapshots and dumps. Appended files the package cannot cut by time are listed in the new segment's record (discarded.uncut). Nothing is deleted.

A run halted by the engine's energy check or terminated by the start-up watchdog is refused: the first needs a decision on the accuracy parameters, the second would hang again. A run whose record says running is refused while its engine is alive on this host; otherwise the record is closed from what the stdout shows.

Arguments

  • run_dir: run directory of a pipeline run (RUN_INFO.toml, config.toml, output/)
  • base_dir: directory the engine tree is resolved against; default: that of the run's frozen config.toml, which carries absolute paths

Returns

run_dir as an absolute path. Raises an ArgumentError for a run that cannot be resumed, with the reason.

Cluster Jobs

Nbody6Dynamics.submit_run — Function
submit_run(cfg; base_dir = cfg.config_dir, run_id = "", dry_run = false)
    -> @NamedTuple{run_dir::String, script::String, commands::Vector{String}, job_ids::Vector{String}}

Create a run and submit its chain of scheduler jobs, one engine segment per job, under the [cluster] settings of cfg (cluster.enabled must be set; the [cluster] checks of the configuration are applied again, so a configuration built in memory is held to them too).

The run directory is <runs_dir>/<run_id> (run_id generated as by run_pipeline when empty); a directory that already holds a RUN_INFO.toml is refused, since a run in progress is continued by its own chain or by resume_pipeline. The configuration is frozen with absolute paths into <run_dir>/cluster/config.toml, which the first job reads, and the job script (job_script) is written to <run_dir>/cluster/job.sbatch.

With chain = "dependency", max_segments jobs are submitted at once, each after the first with --dependency=afterok:<previous job> and --kill-on-invalid-dep=yes, so a failed segment cancels the rest of the chain. With chain = "resubmit" one job is submitted, and each job submits its successor while the run is short of its end time (cluster_segment). Every submission is appended to the job ledgers (<run_dir>/cluster/jobs.csv and <runs_dir>/cluster_jobs.csv, see read_job_ledger) as soon as it is made, so a failure part-way through the chain leaves the submissions already made on record.

With dry_run, nothing is submitted and no ledger row is written; the commands are returned with <job k> placeholders for the dependency ids.

Arguments

  • cfg: the run's configuration, with cluster.enabled = true
  • base_dir: directory the relative paths of cfg resolve against
  • run_id: name of the run directory; empty = generated
  • dry_run: render and write the run's files without submitting

Returns

A named tuple: run_dir, script (path of job.sbatch), commands (the submission command lines) and job_ids (empty for a dry run).

Example

cfg = load_config("campaign.toml")    # [cluster] enabled = true
sub = submit_run(cfg; dry_run = true)
foreach(println, sub.commands)
sub = submit_run(cfg)
sub.job_ids                           # e.g. ["4711"]

Nbody6Dynamics.cluster_segment — Function
cluster_segment(run_dir) -> Dict{Symbol,Any}

Entry of a scheduler job (scripts/run_cluster_segment.jl): run one engine segment of the run in run_dir and, with chain = "resubmit", submit the job of the next one.

The configuration is read from <run_dir>/config.toml when it exists, else from <run_dir>/cluster/config.toml. The latter is the copy frozen at submission and serves only the first job; from the first segment on, <run_dir>/config.toml holds the whole configuration, [cluster] included, and is the single source of truth for both the engine segment and the chain (chain, max_segments, sbatch, the job script). Changes between jobs, such as a different simulation.wall_budget, are therefore made in <run_dir>/config.toml.

Without a RUN_INFO.toml the pipeline is started (run_pipeline with the run id basename(run_dir)), otherwise it is continued (resume_pipeline). The job id is taken from SLURM_JOB_ID (empty outside a job); the ledgers receive a started row before the segment and an ended row with the run status and the segment count after it, or with status error and the exception's message before the exception propagates. The scheduler's job description is kept as cluster/job_<job_id>.txt when scontrol is available.

A successor <sbatch> --parsable --dependency=afterany:<job_id> cluster/job.sbatch is submitted when chain = "resubmit", the run status is none of completed, halted, watchdog, the pipeline has not finished, and the segment count is below max_segments (0 = no bound); the script is regenerated from the configuration if it is missing.

Returns

The result of the pipeline call: empty while the run is short of its end time, and once its pipeline has finished.

Example

# what the generated job script runs, within a Slurm job
results = cluster_segment("/scratch/runs/merger_run_20261013_120000_ab12")

Nbody6Dynamics.job_script — Function
job_script(cfg, run_dir; base_dir = cfg.config_dir) -> String

Text of the sbatch script that runs one segment of the run in run_dir (resolved against base_dir when relative) under the [cluster] settings of cfg. Nothing is written; submit_run stores the text as <run_dir>/cluster/job.sbatch.

The #SBATCH header carries the job name (cluster.job_name, else the run id), the partition, account, QOS, memory and generic resources when set, the node, task and CPU counts, --exclusive when requested, the time limit, --signal=B:TERM@<stop_margin> (the signal time clamped to 1–65535 s, the range Slurm accepts) and the output file <run_dir>/cluster/slurm_%j.out, followed by the cluster.sbatch_options verbatim. The body runs the cluster.prologue lines, sets JULIA_NUM_THREADS (cluster.julia_threads, or the job's SLURM_CPUS_PER_TASK with cluster.cpus_per_task as the fallback outside a job) and execs Julia on the package's scripts/run_cluster_segment.jl. The exec makes the Julia driver the batch shell itself, so the signal Slurm sends ahead of the time limit reaches the driver, whose exit hook stops the engine with a dump.

Arguments

  • cfg: configuration whose [cluster] and simulation.stop_margin are rendered
  • run_dir: run directory (<runs_dir>/<run_id>)
  • base_dir: directory a relative run_dir is resolved against

Returns

The script text, ending in a newline.

Nbody6Dynamics.estimate_cost — Function
estimate_cost(cfg; n, span_nb, nnbopt = 0, dtadj = 0.0, deltat = 0.0,
              merger = cfg.merger.enabled) -> CostEstimate

Wall time, segments and disk of an engine run of n bodies over span_nb N-body time units.

The rate is cost_rate on cfg.cost.table (the built-in H200 table when empty), multiplied by cfg.cost.merger_factor for a two-cluster configuration (merger); the wall time is the rate times span_nb. With a non-zero simulation.wall_budget the number of segments is the wall time over wall_budget − stop_margin, rounded up; otherwise 1.

The disk is the sum of

  • restart dumps: checkpoint_keep of them when it is non-zero, otherwise one per adjustment interval dtadj (⌊span_nb/dtadj⌋ + 1), at least one terminal dump; each of the size of _checkpoint_dump_bytes(n, nnbopt);
  • conf.3 snapshots, 40 bytes per body at each of ⌊span_nb/deltat⌋ + 1 outputs (none when deltat = 0);
  • sev.83 and bev.82 text, about 130 bytes per star at each output.

exceeds is set when cfg.cost.budget_hours > 0 and the wall time is longer than the budget.

Arguments

  • cfg: the configuration ([cost], simulation.wall_budget, simulation.stop_margin, simulation.checkpoint_keep)
  • n: particle number (an integral value)
  • span_nb: integrated span [N-body time units], > 0
  • nnbopt: target neighbour number of the dump estimate, ≥ 0
  • dtadj, deltat: adjustment and snapshot intervals [N-body time units], ≥ 0; 0 = not known
  • merger: apply cost.merger_factor

Example

e = estimate_cost(cfg; n = 500_000, span_nb = 100, nnbopt = 300, dtadj = 1.0, deltat = 10.0)
e.wall_s        # 28100.0 with the built-in table

Nbody6Dynamics.cost_rate — Function
cost_rate(n; table = _COST_TABLE_H200) -> Float64

Wall seconds per N-body time unit of an engine run with n bodies: log–log linear interpolation between the two table rows that bracket n; outside the table, extrapolation with the exponent of the nearest segment.

Arguments

  • n: particle number, > 0
  • table: rows (N, s_per_nb) with strictly increasing N and positive rates, at least two; tuples, or the two-element vectors of cost.table. The default is the built-in H200 table (_COST_TABLE_H200)

Raises an ArgumentError for a table with fewer than two rows, unordered N or non-positive entries.

Example

cost_rate(5e5)                                     # 281.0
cost_rate(2e5; table = [[1e5, 60.0], [1e6, 1000.0]])

Post-process Nbody6++ output from an arbitrary directory.

This is the config-free entry point: no Nbody6Config or config.toml required. The function scans dir for all recognised output files (using the standard Nbody6++ file names), reads whatever is available, runs sanity checks, and optionally generates plots and animations through the same generate_plots dispatcher as the config-driven pipeline.

Arguments

  • dir: directory containing Nbody6++ output files (conf.3_*, out1000, lagr.7, etc.)
  • output_dir: where to save plots (default: <dir>/../plots/)
  • format: plot format — "pdf" (vector default), "svg", "png"
  • dpi: raster resolution at final print size (png only)
  • column: "single" | "double" journal-width preset
  • units: "physical" | "nbody" axis units
  • make_plots: set false to skip plot generation (returns data only)
  • make_animations: set false to skip GIF animations (faster)

Returns

A Dict{Symbol,Any} with keys :scan, :snapshots, :diagnostics, :lagr, :escapers, :stellar_evo, :binary_evo (present only if corresponding data exists), the same keys the config-driven pipeline produces.

Example

using Nbody6Dynamics

# Point at any directory with Nbody6++ output
results = postprocess_external("/scratch/sim42/output")

# Or data-only (no plots):
results = postprocess_external("/scratch/sim42/output"; make_plots=false)

# Inspect what was found:
results[:scan]  # OutputScan with availability info

Nbody6Dynamics.shrinking_sphere_centre — Function
shrinking_sphere_centre(pos, mass; weights = :number, shrink = 0.025, n_stop = 1000,
                        stop_fraction = 0.01, n_floor = 500)
    -> (; centre::Vector{Float64}, radius::Float64, n_final::Int, sigma::Float64)

Centre of a particle set by the shrinking-sphere iteration of Power et al. (2003, DOI 10.1046/j.1365-8711.2003.05925.x). Starting from all particles, the centre is the centroid of the current set; the set is then reduced to the max(n_f, round(Int, (1 − shrink) n)) particles closest to that centre (at least one particle is dropped per step) and the centroid is recomputed, until at most n_f particles remain.

The stop count follows Power et al.: 1000 particles or 1 % of the set, whichever is smaller, with a floor of 500 particles or half the set, whichever is smaller,

n_f = max(min(n_stop, ⌈stop_fraction N⌉), min(n_floor, ⌈N/2⌉)).

Sets of at most two particles return their centroid directly.

Arguments

  • pos: 3 × N positions
  • mass: N masses
  • weights: :number (plain centroid) or :mass (mass-weighted centroid)
  • shrink: fractional reduction of the set per step, in (0, 1)
  • n_stop, stop_fraction, n_floor: stop rule above

Returns

  • centre: final centre
  • radius: distance from the centre to the farthest particle of the final set
  • n_final: particles in the final set
  • sigma: per-axis centre noise radius / √(5 n_eff), the standard error of the centroid of a uniform sphere, with n_eff = n_final for :number and n_eff = (Σm)² / Σm² over the final set for :mass

Number weighting is the default: with a broad mass spectrum a mass-weighted centre locks onto the few massive stellar remnants instead of the stellar density maximum.

Example

c = shrinking_sphere_centre(pos, mass).centre

Nbody6Dynamics.lagrangian_grid — Function
lagrangian_grid(pos, mass, centre; fractions = LAGR_MASS_FRACTIONS, weights = :mass, n_min = 100)
    -> (; fractions::Vector{Float64}, radii::Vector{Float64}, masked::BitVector,
          sigma_log::Vector{Float64}, n_eff::Float64)

Lagrangian radii about centre on a grid of enclosed fractions, with the entries that the particle number cannot resolve masked.

With weights = :mass the radius r_f encloses the fraction f of the total mass and the effective particle number is N_eff = (Σm)² / Σm²; with weights = :number it encloses the fraction f of the particle count and N_eff = N.

Masking

An entry is masked (masked[k] = true, radius NaN) when

f N_eff < n_min  or  (1 − f) N_eff < n_min  or  f ≥ 1,

i.e. when fewer than n_min effective particles lie inside or outside the radius. The 100 % radius is the maximum order statistic of the radial distribution and is never usable.

Noise

The enclosed fraction is binomial, δ ln M = √((1 − f) / (f N_eff)) (Giersz & Heggie 1994, DOI 10.1093/mnras/268.1.257), and propagates to the radius through the local logarithmic slope of the mass profile,

σ(ln r_f) = √((1 − f) / (f N_eff)) / (d ln M / d ln r).

The slope is the central difference ln(f₊/f₋) / ln(r₊/r₋) between the nearest unmasked neighbouring fractions, one-sided at the ends of the unmasked run; sigma_log is NaN where an entry is masked or the slope cannot be formed or vanishes.

Arguments

  • pos: 3 × N positions; mass: N masses; centre: reference point
  • fractions: enclosed fractions in (0, 1], ascending (default: the 18 fractions of the engine's lagr.7)
  • weights: :mass or :number
  • n_min: minimum effective particle number on either side of a radius

Example

g = lagrangian_grid(pos, mass, shrinking_sphere_centre(pos, mass).centre)
r_h = g.radii[findfirst(==(0.5), g.fractions)]

Nbody6Dynamics.relaxation_times — Function
relaxation_times(pos, vel, mass, centre; gamma = (0.02, 0.11), rho_core = NaN, sigma_core = NaN)
    -> (; t_rh::NTuple{2,Float64}, t_rc::NTuple{2,Float64}, t_cr::Float64, r_h::Float64,
         sigma_3d::Float64, m_mean::Float64, n::Int)

Half-mass and core relaxation times and the crossing time of a particle set in N-body units (G = 1).

  • Half-mass relaxation time (Spitzer 1987, Dynamical Evolution of Globular Clusters, Princeton University Press; the form quoted by Baumgardt 2001):

    t_rh = 0.138 √N r_h^{3/2} / (√m̄ ln(γ N)),

    with r_h the half-mass radius about centre and m̄ = M/N.

  • Core relaxation time (Giersz & Heggie 1994, DOI 10.1093/mnras/268.1.257), from the core density rho_core and the one-dimensional core dispersion sigma_core:

    t_rc = 0.338 σ_c³ / (m̄ ρ_c ln(γ N));

Nbody6Dynamics.coalescence_time — Function
coalescence_time(snaps, cluster_ranges; bound_sets = nothing, max_passes = 100, min_members = 10)
    -> (; index, time_nb, time_myr, n_distinct::Vector{Int},
         separation::Matrix{Float64}, threshold::Matrix{Float64},
         pairs::Vector{Tuple{Int,Int}}, present::BitMatrix)

First snapshot from which the initial clusters form a single spatial group for the rest of the run.

At every snapshot each cluster (tag of cluster_ranges) is represented by its members that belong to the bound set of the whole system (bound_set of the snapshot with max_passes and min_members, or the entries of bound_sets, one per snapshot, when the caller has them); a cluster with fewer than 2 × _MIN_MEMBERS bound members is absent at that snapshot. Its centre is the shrinking-sphere density centre of those members and r_h their half-mass radius about it. The members are taken from the global bound set, not from a bound set of the tag alone: after the merger the stars of the smaller cluster are bound to the remnant, not to each other, and a per-tag unbinding would strip them away. Two present clusters are merged when their centres are closer than min(r_h,i, r_h,j); n_distinct counts the connected components of the merged-pair graph over the present clusters (union–find). The clusters have coalesced at snapshot k when n_distinct == 1 with at least two clusters present there and n_distinct == 1 at every later snapshot, so a first passage through the pericentre of an orbit that separates again does not count (Fellhauer et al. 2002, doi:10.1046/j.1365-8711.2002.05143.x).

The criterion replaces one based on member centres of mass and RMS radii: the RMS radius of a Plummer sphere diverges logarithmically with the truncation radius, and the member centre of mass follows the stripped debris rather than the cluster.

index is nothing and the times are NaN when the clusters never coalesce within the snapshots. separation and threshold are n_pairs × n_t in the pair order (1, 2), (1, 3), …, (2, 3), …, NaN where a cluster of the pair is absent. One bound-set evaluation per snapshot unless bound_sets is given.

Nbody6Dynamics.rotation_analysis — Function

                  stop_fraction = 0.01, n_floor = 500)

         lambda_peebles_floor_analytic, v_peak, r_peak, profile)

Rotation of a bound set about its shrinking-sphere centre (shrink, n_stop, stop_fraction and n_floor go to shrinking_sphere_centre).

L is the angular momentum of the whole set about its centre and mass-weighted mean velocity. The spin axis is the unit vector of the angular momentum of the particles within 2 r_h of the centre, about their own mean velocity ([0, 0, 1] when it vanishes), so that loosely bound outer stars and tidal debris do not tilt it; r_h is the half-mass radius about the centre unless passed.

The RotationProfile uses cylindrical shells of equal membership, max(1, min(nbins_max, ⌊N / n_min⌋)) of them; the mass-weighting noise of a shell is measured by the sign-flip null rather than assumed through N_eff = (Σm)² / Σm², which enters the analytic λP floor only. (2018, doi:10.1093/mnras/sty2225) to the shells within 3 r_h, weighted by membership: R_pk on a logarithmic grid of 64 values across the shell radii, V_pk the linear least-squares amplitude; NaN with fewer than two shells.

spin_axis fixes the axis instead of deriving it from the particles within 2 r_h, so that subsets (a radial range, a mass class) are measured about the axis of the whole set.

The radii r_f enclosing the fractions of the particle count bound the shells: shell k starts as the spherical shell r_{f_{k−1}} < r ≤ r_{f_k} (r_{f_0} = 0). At each iteration the members are the particles with elliptical radius r_e² = x_a² + x_b²/q² + x_c²/s² (coordinates in the current eigenframe) in (r_{f_{k−1}}, r_{f_k}], the tensor is S = (1/n) Σ x xᵀ over their positions relative to centre, and its eigenvalues a² ≥ b² ≥ c² give the new q = b/a, s = c/a and the new frame. The iteration starts from q = s = 1 in the coordinate frame and stops when both ratios change by less than tol, or after max_iter iterations (converged = false).

The tensor is unweighted: the r⁻²-weighted (reduced) tensor gives inner particles of a shell more weight and biases the result towards rounder shapes (Allgood et al. 2006, DOI 10.1111/j.1365-2966.2006.10094.x).

A shell needs a few thousand members for the ratios to be meaningful: with n members, a spherical sample returns 1 − E[c/a] ∝ n^{−1/2}, so small departures from sphericity are interpreted against a Plummer null of the same count. Shells with fewer than n_min_shell members at convergence, or fewer than n_min_enclosed particles inside their outer ellipsoid, are returned with q = s = NaN and the remaining fields filled.

Nbody6Dynamics.snapshot_pairs — Function
snapshot_pairs(pos, vel, mass; k = 10, tidal_factor = 1/3, kT = NaN)
    -> Vector{SnapshotPair}

Bound pairs among the stars pos, vel (3 × n) of masses mass, G = 1 in any consistent units, sorted by decreasing binding energy.

Candidates are the unordered pairs (i, j) in which j is one of the k nearest neighbours of i or vice versa, found on a k-d tree. For each candidate the relative orbit gives the specific energy $ε = |\mathbf{v}|^2 / 2 - μ / |\mathbf{r}|$ with $μ = m_i + m_j$; a bound candidate (ε < 0) has $a = -μ / (2ε)$ and $e = \sqrt{1 - h^2 / (a μ)}$, h the specific angular momentum. Bound candidates are joined in ascending ε, most bound first, and a pair is accepted only when neither star belongs to an accepted pair: the first level of the node joining of Bate (2009, DOI 10.1111/j.1365-2966.2009.14165.x). Hierarchical nodes (an accepted pair bound to a third body) are not built, so a triple appears as its inner pair. Coincident stars, whose relative orbit is undefined, are not paired.

The candidate restriction means that a pair is found only when it is closer than the k-th neighbour of at least one of its stars; wide soft pairs beyond that distance are not searched.

Two-body boundedness ignores the environment: a pair that is bound in isolation but sits inside a dense core is tidally unbound. tidal_ok flags the pairs whose apocentre a(1 + e) stays within tidal_factor times the distance r_third from the pair's centre of mass to the nearest other star.

kT is the hard/soft energy scale in the units of the input, typically $⟨m⟩ σ_\mathrm{1D}^2$ of the bound set (in N-body units, the hardness_scale product m_mean * sigma_kms^2 divided by zmbar * vstar^2); hardness = E_b / kT and a pair is hard when hardness > 1 (Heggie 1975, DOI 10.1093/mnras/173.3.729).

The components of the engine's KS pairs are stored in a snapshot at their predicted positions and velocities, so the finder's elements for those pairs agree with the engine's up to the single-precision rounding of the file.

Throws ArgumentError unless k ≥ 1, tidal_factor > 0, kT is positive or NaN and there are at least two stars, and DimensionMismatch unless pos and vel are both 3 × length(mass).

Example

pairs = snapshot_pairs(Float64.(snap.pos), Float64.(snap.vel), Float64.(snap.mass); kT)
count(p -> p.tidal_ok && p.hardness > 1, pairs)

Nbody6Dynamics.angular_momentum_budget — Function

Angular-momentum budget of a snapshot series and the rotation of its bound sets, in N-body units (see AngularMomentumBudget). Stars are identified across snapshots by name.

The budget follows the internal angular momentum of all stars, about their centre of mass and mass-weighted mean velocity (l_total), between consecutive snapshots k − 1 and k. The internal angular momentum is invariant under translations and boosts of the frame, so the engine's centre-of-mass corrections after escaper removals do not enter it. The stars absent from k carry off the difference between the internal angular momentum of snapshot k − 1 with and without them (l_removed); the stars new in k bring the same difference at k (l_added); the stars common to both snapshots shed, with their mass loss, the difference between their internal angular momentum with the earlier and with the later masses, evaluated at either snapshot's phase space and averaged (l_stellar). The stars that became remnants in the interval, named by the engine's remnant_formation and kick_* events of events (name1, event time in (t_{k−1}, t_k]), are left out of the shed term; the change of the internal angular momentum they cause, the difference between the common set with and without them at k minus the same at k − 1, is their own term l_remnant (the natal kick and the mass loss of the remnant together). residual = l_total + l_removed − l_added + l_stellar − l_remnant − l_total(t₁),

which vanishes exactly for stars removed, masses changed or remnants kicked at fixed phase space of the others, and otherwise measures the torque of the departing stars on the rest between the last snapshot that holds them and their removal, together with the integration error (isolated run) or the tidal torque (external field). A configuration with little net rotation has |l_total| far below its angular-momentum content, so the residual is judged against l_scale, not against |l_total|.

Nbody6Dynamics.sample_plummer_om — Function
sample_plummer_om(N::Int, a::Float64, r_a::Float64; rng = Random.default_rng()) -> (pos, vel)

Osipkov–Merritt anisotropic Plummer model of N equal-mass particles with scale radius a and anisotropy radius r_a (Merritt 1985, DOI 10.1086/113810). The density is that of the Plummer sphere, ρ = 3/(4π a³) (1 + r²/a²)^{-5/2}; the velocity anisotropy is β(r) = r²/(r² + r_a²), isotropic inside r_a and radially biased outside. r_a is in the same length units as a; r_a = Inf gives the isotropic Plummer model.

The distribution function follows from Eddington inversion in the variable Q = E + L²/(2r_a²): the augmented density ρ_Q = (1 + r²/r_a²) ρ is a polynomial in the relative potential ψ = (1 + r²/a²)^{-1/2}, so with x = a²/r_a² the inversion gives the closed form f(Q) ∝ (128/7)(1 − x) Q^{7/2} + 8x Q^{3/2}, which for x = 0 reduces to the isotropic Plummer distribution function ∝ (−E)^{7/2}. It is non-negative for all bound orbits only when x ≤ 16/9, i.e. r_a ≥ 0.75 a; smaller r_a is rejected.

Positions are drawn by the inverse CDF as in sample_plummer; speed and pitch angle by von Neumann rejection from the distribution function at the particle's radius, with a uniformly random azimuth of the tangential velocity.

Returns (pos::Matrix{Float64}, vel::Matrix{Float64}), each 3 × N, in units where G = M_total = 1.

Example

pos, vel = sample_plummer_om(10_000, 1.0, 1.5; rng = Xoshiro(1))

lynden_bell_flip!(vel, pos, axis, p; rng = Random.default_rng()) -> vel

Lynden-Bell (1960) rotation by sign flips (DOI 10.1093/mnras/120.3.204). For every particle off the rotation axis axis (any non-zero 3-vector), the azimuthal velocity v_φ about that axis is given the positive sign with probability p and the negative sign otherwise, by reflecting the velocity in the meridional plane (v ← v − 2 v_φ φ̂). Particles on the axis are left untouched.

The density, the speeds, the radial velocities and every velocity dispersion are unchanged, so an equilibrium stays an equilibrium; the mean azimuthal velocity in any shell becomes (2p − 1)⟨|v_φ|⟩. p = ½ is the non-rotating null, p = 1 the maximal rotation the given model admits. vel is overwritten and returned.

Example

pos, vel = sample_plummer_om(10_000, 1.0, Inf)
lynden_bell_flip!(vel, pos, [0.0, 0.0, 1.0], 0.8)

Nbody6Dynamics.rank_masses_by_energy! — Function
rank_masses_by_energy!(mass, energy, S; rng = Random.default_rng()) -> mass

Mass segregation of tunable degree S, the model of Šubr, Kroupa & Baumgardt (2008, DOI 10.1111/j.1365-2966.2008.13161.x) in its simplest form. A random fraction S of the particles (round(Int, S n) of n) receives the largest masses, ranked so that the most bound of them (lowest energy) carries the largest mass; the remaining masses go to the remaining particles in random order. S = 0 is a random permutation of the masses, S = 1 the full energy ranking.

The mass set is preserved exactly — the result is a permutation of the input — and only its assignment to particles changes; energy (per-particle specific or total energy, any consistent units) is not modified. mass is overwritten and returned.

Example

rank_masses_by_energy!(mass, energy, 0.5; rng = Xoshiro(1))

Nbody6Dynamics.engine_interval — Function
engine_interval(dt; resolution = 1/128, max_digits = 9) -> Float64

dt rounded to the nearest dyadic rational m 2⁻ᵏ whose spacing 2⁻ᵏ is at most resolution × dt, with k ≤ max_digits. Such a value has an exact decimal expansion of k digits, so the engine's digit counter (_engine_digit_counter_terminates) stops after k steps, and it is commensurate with the engine's power-of-two block time steps. The cap of nine digits is the engine's as well: string_left.f formats a count of at most ten with an I1 descriptor, so exactly ten digits produce an invalid format and a runtime error at the next output. Applied to DTADJ, DELTAT and DTPLOT before they are written to merger.inp; the change is below resolution / 2 unless max_digits binds (intervals below about 2⁻ᵐᵃˣ⁻ᵈⁱᵍⁱᵗˢ × 128). dt ≤ 0 is returned unchanged.

Example

engine_interval(0.6302)   # 0.62890625 = 161/256
engine_interval(0.5)      # 0.5

Nbody6Dynamics.to_nbody_units! — Function
to_nbody_units!(mass, pos, vel, M_total_solar, rbar_pc)

Convert from physical units (M☉, pc, km/s) to N-body units (G = 1, Mtotal = 1, length unit `rbarpc`) in-place.

The callers pass the half-mass radius of the whole initial configuration as rbar_pc, and the engine reads the result with KZ(22) = 2, which skips its rescaling to E = -1/4. The total energy is therefore not -1/4: an isolated King W₀ = 6 cluster starts near -0.20 (rV ≈ 1.25 rh), and a bound pair lower still, its orbital binding energy adding to the total.

N-body scaling

  • Mass: m_nb = m_solar / M_total_solar
  • Length: r_nb = r_pc / rbar_pc (rbar = length unit in pc)
  • Velocity: v_nb = v_kms / vstar where vstar = sqrt(G M_total / rbar) in km/s, i.e. _CODE_VSTAR_KMS × sqrt(M_total / rbar).

Nbody6Dynamics.radial_profile — Function
radial_profile(pos, vel, mass, centre; nbins = 12, n_min_inner = 20,
               mass_fraction_max = 0.99, n_min_sigma = 50, n_min_beta = 300,
               n_min_density = 100) -> RadialProfile

Shell profile of the particles about centre (N-body or any consistent units), out to the radius r_max enclosing mass_fraction_max of the mass.

Kinematic shells: the particles with d ≤ r_max are split into max(1, min(nbins, N_used ÷ n_min_sigma)) shells of equal membership, so that the statistical error is the same in every shell. Velocity dispersions carry the relative error δσ/σ = (2(n − 1))^{−1/2} and the anisotropy the standard error σ_β = (1 − β)(3/n)^{1/2}; about 300 members give β to ±0.1 near isotropy, hence the default n_min_beta. sigma_r and sigma_t are NaN below n_min_sigma members, beta below n_min_beta.

Logarithmic density shells: nbins shells whose outer edges are log-spaced between the radius enclosing n_min_inner particles and r_max (the innermost shell is the sphere inside the first edge). From the inside out, each shell is merged with its outer neighbour until it holds at least n_min_density members; a short outermost remainder joins the shell inside it, and a set with fewer than n_min_density particles inside r_max has a single shell.

Arguments

  • pos, vel: 3 × N positions and velocities; mass: N masses
  • centre: reference point, e.g. shrinking_sphere_centre
  • nbins ≥ 2: maximum number of kinematic shells, number of logarithmic shells before merging
  • n_min_inner: particles inside the first logarithmic edge (N ≥ 2 n_min_inner)
  • mass_fraction_max: enclosed mass fraction defining r_max
  • n_min_sigma ≥ 2, n_min_beta ≥ n_min_sigma, n_min_density ≥ 1: membership thresholds above

Example

c = shrinking_sphere_centre(pos, mass).centre
p = radial_profile(pos, vel, mass, c)
lines(p.r, p.beta)

Nbody6Dynamics._engine_digit_counter_terminates — Function
_engine_digit_counter_terminates(dt) -> Bool

Whether the engine's string_left.f terminates on the interval dt. That routine, called at every output (output.F), COMMON dump (mydump.F) and stellar-evolution record (hrplot.F) with DELTAT, DTADJ and DTPLOT, counts the decimal digits of dt by multiplying by ten until dtmp - int(dtmp) is zero, with a default-kind int. A value whose binary representation never lands on an integer under repeated multiplication (0.6302, 0.1576, …) grows past 2³¹, where the conversion overflows, and the loop never ends: the engine sits at 100 % CPU inside its first output and never prints a second adjustment. Emulated here in the same arithmetic.
