1. Introduction

Nbody6Dynamics.jl drives Nbody6PPGPU-beijing simulations from one config.toml: it clones and compiles the engine, optionally generates the initial conditions (Multi-Cluster Merger Simulations), runs and supervises the integration, reads the output into Julia structures, computes the diagnostics and draws the figures and GIF animations.

Every parsed key of the configuration and its default is listed below. The single entry point is:

cfg = load_config("config.toml")
results = run_pipeline(cfg)

The directory of that file is the project directory: every relative path in the configuration (install.install_dir, simulation.input_file, simulation.runs_dir, postprocess.data_dir, merger.config_file) resolves against it, and the engine tree and the run directories are created there. load_config records it as cfg.config_dir, which is the default base_dir of every entry point; a configuration built in memory takes the working directory. Nothing is ever written under the package's own tree, so an installation by URL (Pkg.add(url = ...)) and a checkout behave alike; the inputs the package ships are reachable either way through example_input("N1k_quick.inp").

2. Prerequisites

  • Linux (tested on Fedora and Ubuntu)
  • Julia 1.13+ through juliaup, the version the package is developed and validated on. Manifests are not under version control: each environment resolves from its Project.toml on first activation, and every run stores the manifest it resolved as environment_manifest.toml
  • GCC toolchain: gcc, g++, gfortran, make
  • Git (for cloning the simulation code)

Optional, depending on config: MPI (mpicc, mpif90, mpirun), CUDA toolkit (nvcc), HDF5 development headers (hdf5-devel / libhdf5-dev) for the build-side HDF5 patch.

3. Installation

cd Nbody6Dynamics.jl
julia activate.jl                                   # resolves, instantiates and precompiles the package environment
julia -e 'include("activate.jl"); Pkg.test()'

activate.jl activates and instantiates the package environment silently; docs/activate.jl and bench/activate.jl do the same for the documentation and benchmark environments, developing the package by a relative path. The scripts under scripts/, docs/ and bench/ include their environment's activation script, so they run without a project flag. The first using Nbody6Dynamics after an install or a source change precompiles the package together with a small workload (configuration parsing, the diagnostics reader, a merger initial-condition generation), so those paths run compiled in every later session.

4. Configuration Reference

Every key below is parsed by load_config (src/config.jl). Missing keys fall back to the defaults shown, which are those of the configuration structs. All constraints listed below are enforced fail-fast at load time: load_config raises an ArgumentError naming the offending section.key and the actual value — a key the schema does not define, a value of the wrong type, a choice outside the enumerated ones, a number outside its bounds — so a pipeline cannot start from a configuration it cannot honor, and a misspelt key cannot run silently at its default. save_config writes a frozen snapshot of the full configuration into each run directory, with its paths made absolute.

5. Pipeline Modes

run_pipeline executes up to five phases, each controlled by config flags:

PhaseControlled byNotes
1. Install/Buildinstall.enabledClone + compile Nbody6++
1.5 Merger ICsmerger.enabledGenerate dat.10 + merger.inp into a new runs/merger_<prefix>_.../output/ directory
2. Simulationsimulation.run_testRun the N-body integration (with merger ICs when phase 1.5 ran)
3. Post-processpostprocess.enabledReaders, diagnostics, derived tables and the validity record
4. Plotsvisualization.enabledStatic plots + GIF animations

Common configurations:

  1. Full pipeline: install.enabled=true, simulation.run_test=true
  2. Simulate only: install.enabled=false, simulation.run_test=true
  3. Postprocess only: simulation.run_test=false, postprocess.data_dir="/path/to/output"
  4. Re-plot latest run: simulation.run_test=false, postprocess.data_dir="" — the most recent run under runs/ (plain or merger) is post-processed
  5. Merger ICs: merger.enabled=true, merger.config_file="input_files/..." (with run_test=false to only generate)
  6. Merger + simulate: merger.enabled=true, simulation.run_test=true — the binary runs inside the merger output directory so dat.10 is found in its working directory

A simulation phase that ends on a stop request (simulation.wall_budget, or a signal to the driver) ends the pipeline there: phases 3 and 4 belong to the completed run, and post-processing a large run once per segment would cost more than the segment's margin. resume_pipeline(run_dir), or julia scripts/run_resume.jl <run_dir> from a shell, starts the next segment from the configuration frozen in the run directory and, once the run has reached its end time, performs the remaining phases and stamps the pipeline as complete. It can be called any number of times: a job per queue segment needs no knowledge of how many segments the run will take, and a call on a finished run does nothing.

For output produced entirely outside this project there is also the config-free path:

results = postprocess_external("/scratch/sim42/output")   # scan + read + plot

6. Build Phase Details

HDF5 build patching

With enable_hdf5 = true the build adds the HDF5 compiler and linker flags and -DCONFIG_HDF5 to the engine Makefile. This engine version reads no CONFIG_HDF5 symbol: its H5Part writer is compiled only under H5OUTPUT, which the package does not define, so the setting changes nothing in what the binary writes. The package reads no .h5part file in any case; scan_output reports them.

Source amendments

The package's engine fork carries the corrections below as commits on its main branch (the default install.source_url and install.ref), and a build from it finds them in place. For a build from an upstream checkout, the install phase applies the same corrections before configure from the package's deps/engine/amendments.toml. Each is an exact text substitution in one file, for a defect met in production runs:

An amendment whose text does not occur exactly once in the tree, as with another engine revision, is skipped with a warning and listed under source_amendments_skipped; the build then proceeds on the unamended source. On an upstream checkout backend_commit carries -dirty: the substitutions are local modifications, and configure rewrites two tracked files (config.log, include/params.h). The fork tracks neither and ignores the build outputs, so a build from its tag records a clean commit, and -dirty there means a hand-edited tree. Further corrections are made as commits of the fork, not as amendments; the fork's NOTICE.md lists all of them by tag (among them the hang of an output interval without a short exact binary expansion, the end-of-run dumps skipped under NCOMM > 1, and the thread limit of the AVX build). An existing checkout under install_dir is reused as it is (whatever its origin); reinstall = true replaces it with a fresh clone of source_url at ref.

CUDA auto-detection

When enable_gpu = true and cuda_path is empty, the build searches in order:

  2. Standard paths: /usr/local/cuda, /usr/local/cuda-12, /usr/local/cuda-11.8, …

Other facts of the GPU build:

  • The binary is named after the configure options: nbody6++.avx.gpu (and nbody6++.avx.mpi.gpu with MPI). CPU and GPU binaries may coexist in build/; the launcher picks the variant whose suffix tags match enable_gpu/enable_mpi. Switching one source tree between CPU and GPU builds requires clean_build = true, because the Fortran objects are compiled with -D GPU in one case only and make does not track the flag change.
  • BUILD_INFO.toml is written next to the binary (date, host, backend commit, configure arguments, switches, CUDA path, compiled architectures, nvcc release). Every run copies it into its output directory and merges it into RUN_INFO.toml as the [build] table.
  • One engine process drives at most four devices (MAX_GPU in the kernel source): with gpu_list empty it takes every visible device, otherwise those listed, and splits the regular-force j-range evenly across them by one OpenMP thread per device. The kernels compute in single precision on every architecture.
  • The GPU library reports the devices it initialised on stderr; the run summary records them as run.gpu_devices, and the kernel throughput profile carries the label GPU Reg.F in telemetry.force_kernel_gflops.kernel, so a run that silently fell back to the CPU path is visible.
  • The upstream advice to use the GPU build only above a few 10⁴ bodies is superseded by the measurement in Validated hardware: on every host tested the GPU binary was faster at every size, and any crossover lies below N ≈ 2×10⁴; bench/gpu_scaling.jl measures it on a new host.
  • HDF5 output is unnecessary for the Julia side (it reads conf.3), so a GPU build can use enable_hdf5 = false.

A stage is judged by what it produced, not only by how it exited. A stage killed by a signal is recorded with that signal, separately from its exit code. Whether it is run again is a policy with three settings: max_retries (default 1), retry_signals (default the crash signals SIGILL, SIGABRT, SIGBUS, SIGSEGV = 4, 6, 7, 11) and retry_stages (default the test suite only); on the command line --max-retries=, --retry-signals= and --retry-stages=. The output of every retried attempt is kept as <stage>.attempt<k>.signal<N>.log, the signals are listed under retried_signals, and the policy in force under [retry] in VALIDATION.toml. A retried pipeline stage starts from a clean run directory; the crashed attempt's runs/<run_id> is kept as runs/<run_id>.attempt<k>.signal<N>.

The toolkit need not be on PATH: the build looks at CUDA_HOME, /usr/local/cuda and the other standard locations, or at cuda_path, and exports the toolkit's bin and lib64 to configure, make and the launch script; configure also receives --with-cuda=<path>. The engine's configure finds nvcc only on PATH (its --with-cuda fallback reuses the cached result of the PATH check), which is why the exported PATH matters. CUDA 13 toolkits work: the engine's own copy of helper_cuda.h reads cudaDeviceProp fields that CUDA 13.0 removed, so the build places the package's deps/cuda (NVIDIA's current samples headers) ahead of it in the nvcc include path. A host compiler newer than the toolkit supports (CUDA 13.x accepts GCC up to 15; Fedora 44 ships GCC 16) needs a compatible one for the CUDA host code only: install the distribution's side-by-side compiler (sudo dnf install gcc15 gcc15-c++ on Fedora, which provides g++-15; gcc14-c++ likewise) and the build picks it up through -ccbin on its own, or point nvcc_flags = ["-ccbin", "<path>"] at any supported g++. Fortran and the rest of the engine still compile with the system toolchain. A glibc newer than the toolkit supports is the other obstacle: glibc 2.42 and later (Fedora 43/44, Ubuntu 26.04, Debian 13) declare rsqrt and rsqrtf with an exception specification that CUDA 13.1's crt/math_functions.h lacks, and nvcc then rejects every host compiler with "exception specification is incompatible". The probe recognises the message and adds -U_GNU_SOURCE -D_DEFAULT_SOURCE, which keeps glibc's GNU-extension declarations out of the CUDA sources; the engine's GPU sources use none of them. The alternative is to patch <toolkit>/targets/x86_64-linux/include/crt/math_functions.h, adding noexcept(true) to the two declarations, which needs root and is undone by a toolkit update.

To use one binary on several machines set cuda_arch = ["sm_90", "sm_120"] explicitly; gpu_list = [0, 1] puts two devices in one process.

Launch script

The generated _launch.sh sets ulimit -s unlimited (Fortran stack), OMP_STACKSIZE=4096M, OMP_NUM_THREADS when simulation.omp_threads > 0, GPU_LIST when simulation.gpu_list is nonempty, CUDA environment variables (if GPU enabled), and stdbuf -oL for line-buffered output where available. The script stays the parent of the engine: it starts the engine (or mpirun) in a subshell that ignores SIGTERM, writes the engine's process id to output/engine.pid while the engine runs, and waits. A SIGTERM sent to the script becomes the STOP file of a stop request (Wall budget and stop requests); the script exits with the engine's exit status and re-raises on itself the signal that ended the engine, so the segment record shows the engine's end. The record carries both ids: pid is the script, the process a stop request (SIGTERM) is addressed to, engine_pid the engine. A SIGKILL of the script alone cannot be trapped and orphans the engine; the package kills the process group instead, and an operator who must kill by hand kills engine_pid. The backend takes its thread count from the OpenMP runtime alone (there is no input parameter for it) and echoes it at start-up; that echoed value is recorded as run.omp_threads_reported in RUN_INFO.toml next to the configured run.omp_threads, run.mpi_ranks and run.gpu_list; the devices the GPU library initialised appear as run.gpu_devices, and the binary's build record as the [build] table.

Choosing the thread count

The backend's OpenMP parallelism saturates early for the particle numbers a workstation handles: on a 22-thread machine the two-cluster benchmark (bench/thread_scaling.jl) reaches its shortest wall time at four threads for N ≤ 2×10⁴, while more threads only add CPU time (efficiency 0.38 at 22 threads). Parameter sweeps and ensembles are therefore best run as several four-thread jobs in parallel; the benchmark script sweeps thread count and N on your hardware and reports the fitted cost, using the telemetry of each run.

Choosing the GPU devices

bench/gpu_scaling.jl runs the same two-cluster case with the CPU and the GPU binary over a grid of N, thread counts and GPU_LIST values, and prints the GPU speed-up at equal N and threads together with the backend's regular-force share and the kernel throughput. The regular force grows as N² against N⟨Nnb⟩ for the neighbour force, so its share, and with it the gain from the GPU, rises with N; at N = 2×10⁴ it is two thirds of the backend CPU time on the reference workstation, which bounds the gain there at about 3×. Two devices in one process (`gpulist = [0, 1]) halve only the regular-force term, so they pay off later in N than the first device. Under MPI every rank on a host applies the samegpulist; per-rank device slicing is not provided.bench/gpucells.jlis the device-side counterpart for large cells: a grid of (cell, N, host threads,GPULIST, MPI ranks) points, the single cell being one King cluster at rest and the dual cell the two-cluster case, run with post-processing off and read back into one CSV row per run (wall time, the backend timing table, kernel throughput, GPU utilisation, power and memory, host RSS and CPU efficiency, the machine identity and the run ID); a failed run is recorded and the grid continues.julia bench/gpucells.jl –cells=single,dual –n=1000000 –threads=8 –gpus="0;0,1" –tcrit=2.0is a strong-scaling pair on a two-device node;–cpuadds the AVX rows and–mpi-ranks=2runs the device rows on an MPI+CUDA tree.bench/gpucellsfigures.jldraws two figures from any set of those CSVs: the multi-device scaling of the machine that ran with two devices (strong scaling as speed-up against the device count for the regular-force share and the wall time, weak scaling with N ∝ D, host-thread scaling) and the cross-hardware chart of every card (wall time on a log axis with a tick at the regular-force share, and the kernel rate as a fraction of the FP32 peak from a–cardstable, which also sets the axis order and the datacenter / consumer divider). The backend timers are summed over threads, so the figures use their shares of the wall time.–synthetic` fabricates a data set to rehearse the layout.

The indices of gpu_list are those of nvidia-smi, the PCI-bus order: with a non-empty list the launch script exports CUDA_DEVICE_ORDER=PCI_BUS_ID next to GPU_LIST, so the engine and the telemetry mean the same device by an index. Without that setting the CUDA runtime numbers the devices fastest first, which differs from the nvidia-smi order on a host with unlike devices. The GPU columns of the telemetry cover the devices of the list only; with an empty list they average and sum over every device of the host.

Completion detection

The engine prints END RUN (with the final timing tables) when its termination criterion is met, and normally exits right after. In a tidal-field run it has been seen to print everything and then never exit, which blocked the pipeline until an external timeout. With simulation.exit_grace > 0 a monitor watches the last 64 KiB of the stdout capture for that line and, once no file of the output directory has changed for the grace period with the process still alive, terminates it. The engine writes its final COMMON dump after END RUN when KZ(1) > 0; that write keeps the directory changing, so a dump of any size is never interrupted. The segment then carries completed = true, terminated_after_completion = true and the signal exit status, post-processing proceeds, and the sweep summary counts the point as completed (completed column) even though its exit status is nonzero. A run that never printed END RUN is never touched by this monitor.

Stopping a run. The engine runs in its own session (detach), so the hangup of a terminal closing above the pipeline never reaches it; for the same reason the terminal's Ctrl-C never reaches it either, and the pipeline forwards an interrupt itself: SIGINT to a pipeline process (kill -INT <pid>, or Ctrl-C in the foreground) raises InterruptException, the handler asks the engine to stop (SIGTERM to the launch script, which the script turns into a STOP file; SIGKILL of the engine's process group 15 s later if it has not exited), closes the segment record with what the stdout shows (stopped with the dump when the engine honoured the request, else killed; stop_requested = "interrupt"), writes nothing further and re-raises. The entry scripts set Base.exit_on_sigint(false) for that, because a Julia script exits on SIGINT at once by default; an interrupt that lands in one of the pipeline's helper tasks (telemetry sampler, watchdogs) is handed to the task waiting on the engine. The validation driver forwards SIGINT to its running stage the same way. A SIGTERM of a pipeline process asks its engines to stop and waits for them (Wall budget and stop requests). A SIGKILL runs no handler and leaves the engine running as an orphan: to end a whole tree at once, signal the engines by name as well, for example pkill -KILL -f 'run_gpu_validation.jl|run_setup.jl|gpu_scaling.jl|nbody6[+][+]', and confirm with pgrep -af 'nbody6[+][+]'. A SIGTERM sent to the engine process itself is ignored (the launch script starts it so); a stop by hand is kill -TERM <pid of _launch.sh> or a STOP file in the output directory. The start-up watchdog and the completion monitor terminate the engine before they log the fact, so a pipeline whose console has gone (its launcher died) still ends the engine it decided to end, and writes its run record and file log. The record's package_commit and backend_commit are captured at launch; a git pull on the host during a run does not change them.

Wall budget and stop requests

A queue with a time limit ends a job whether or not the integration has reached a restart dump. With simulation.wall_budget set, the runner creates the file STOP in the output directory stop_margin seconds before the budget expires. The engine polls for that file every few seconds of wall time; when it finds it, it finishes the current block, writes a dump comm.1_<t> at the time it has reached and exits. The segment is recorded with status = "stopped", stop_requested = "wall_budget", the dump name (stop_dump) and the time (t_end), and the run continues from that dump in a later segment. The dump of a stop is written only if the input has NCOMM = 1 or no periodic dumps (KZ(2) < 1): the engine counts every dump call and writes one in NCOMM, the one at a stop included.

The same request is made by a signal. SIGTERM is what a batch scheduler sends at the time limit and on cancellation, to the driver and, with a plain scancel, to every process of the job. Two things answer it. The launch script, the engine's parent, turns a SIGTERM to itself into the STOP file, while the engine it started ignores SIGTERM (Launch script): a job-wide signal therefore stops the engine with a dump instead of killing it. The driver's exit hook writes STOP for every engine the process has running, waits up to stop_margin seconds for them to exit, terminates those that have not (SIGTERM to the script, SIGKILL of the process group 15 s later), and closes their segment records (stop_requested = "signal"). The engine runs in its own session, so without the hook it would outlive the driver. A stop request left in the output directory is removed when the next segment starts. An operator interrupt (Ctrl-C) makes the same request and records stop_requested = "interrupt".

The wall budget is the dependable path and the signal the second line of defence. The hook relies on Julia's handling of SIGTERM, which serves the signal wherever the main thread happens to be: with the driver waiting on the engine, its state for all but moments of a run, the stop is orderly; a signal that interrupts it in the first seconds after start-up, while code is still being compiled, can block the exit instead. The engine then stops all the same when the signal also reached the launch script, as a scheduler's does; a run whose driver blocked is left with a running record and is continued from the dump like one that crashed. Set wall_budget below the time limit so that the limit is never reached.

With checkpoint = true in [merger.nbody6] the engine also writes a dump at every adjustment, which is what a run that was killed resumes from. Each is of the order of 1 kB per body (642 MB at 6×10⁵ bodies) and the engine never removes one, so a long run accumulates as many as it has adjustments; the generator prints the total. simulation.checkpoint_keep = k deletes all but the newest k while the engine runs. Two is the minimum because a dump being written when the engine dies is incomplete.

Live sparklines

With simulation.live_diagnostics = true (and monitor = true on an interactive terminal) the monitor prints, every live_interval seconds, two in-terminal sparklines built with UnicodePlots from the ADJUST records so far: the virial ratio Q = T/|W| and log10 |ΔE/E| against time (Myr when the scaling is known). The panel is written to stderr below the log lines, the spinner resumes underneath, and nothing of it reaches nbody6dynamics.log. Runs that print fewer than two adjustments show no panel.

Resuming and restarting a run

resume_run(run_dir) continues an interrupted run to the end time of its original input. It reads the last segment's status from RUN_INFO.toml: a completed run is left alone, so the call can be repeated safely; a run that was stopped at its wall budget, killed, or ended by an engine error (failed) gets one more segment from the last complete dump that was not written during a triple, quad or chain regularization (the subsystem counter NSUB in the dump header is zero; the engine cannot restart from any other dump, and builds before v2026.07.6 wrote such dumps at the end of a run and at an energy-check halt). After a stop that dump is the one the engine wrote on request, and the join is exact. After a kill it is the last periodic dump of a checkpointed run, and everything the dead segment wrote after it is first moved to output/discarded/segment_<k>/: the tail of the stdout capture, the later records of lagr.7, global.30, esc.11 and event.35, the later snapshots and dumps. The series the package reads are then single-valued again. The engine's other appended files (coll.13, sediag.38, …) cannot be cut by time; they keep the dead interval, and the new segment's record names them (discarded.uncut) with the interval. A halted run, one ended by the start-up watchdog and one stalled by the stall watchdog are refused, and so is a run whose engine is still alive.

resume_run("runs/merger_demo_20260907_181355_2b7f")

The engine saves its state in COMMON dumps: output/comm.1_<t> when a run ends (END RUN, a stop request, an energy halt) and, with checkpoint = true in [merger.nbody6], output/comm.2_<t> at every adjustment. The time in a file name is rounded to the digits of dtadj; the exact time of each dump is on the engine's MYDUMP line in the stdout capture. For anything else — a chosen dump, more time than the original input asked for — restart_simulation(run_dir; tcrit_extra = 5.0) continues the run from the latest dump (or a chosen one, dump = "comm.2_20.0") for tcrit_extra more N-body time units: the dump is copied to output/comm.1, which KSTART = 2 reads, as a working copy that is removed when the engine exits; the original input recorded in RUN_INFO.toml (run.input_file, copied into output/ at launch) supplies the &ININPUT block of the restart input, with TCRIT set to the increment the engine adds to the saved time, and its &INSSE, &INBSE and &INCOLL blocks, which the engine reads again at a restart (without them non-default stellar, binary-evolution and collision parameters would revert to the Level defaults); the termination time in Myr can be raised with tcrtp0. The engine runs in the same output directory with stdout and stderr appended, so the diagnostics, Lagrangian-radii, and escaper files continue and the time-stamped snapshot and stellar-evolution files carry on; post-processing reads the concatenated run as one. RUN_INFO.toml keeps one entry per launch in segments (kind, dump, extra time, elapsed, exit status), run.elapsed_seconds accumulates, and each segment's telemetry goes to telemetry_<k>.csv. Each entry carries a status: running from the launch until the engine exits, then completed (END RUN printed), stopped (ended at a stop request; resumable), halted (the engine's energy check stopped the run), watchdog, stalled (stopped by the stall watchdog), killed (ended by a signal, or the end was not witnessed) or failed (the engine exited by itself without any of these, as after a runtime error); run.status repeats that of the last segment. The entry is written when the engine starts, with the launch time, host, process id, package commit, the N-body time it starts from (t_start) and the byte length of the stdout capture at that moment (stdout_offset), and is completed at exit with t_end, the elapsed time and the exit status.

restart_simulation("runs/merger_demo_20260907_181355_2b7f"; tcrit_extra = 5.0)

Hardware telemetry

Every run records the exact CPU consumption of the backend process tree from getrusage(RUSAGE_CHILDREN) deltas: cpu_user_s, cpu_system_s, threads_total (effective OpenMP threads × MPI ranks), and cpu_efficiency = (user + system) / (elapsed × threads_total), the fraction of the reserved CPU capacity the integration actually used. These land in the [telemetry] table of RUN_INFO.toml.

With simulation.telemetry_interval > 0 (default 5 s) an asynchronous sampler additionally writes runs/<run_id>/telemetry.csv, one row per interval, with the columns of TelemetrySample: elapsed time, process count, resident memory and high-water mark summed over the tree (from /proc/<pid>/status), cumulative CPU time and the derived cores-busy rate (from /proc/<pid>/stat), the 1-minute load average, and — when build.enable_gpu — one nvidia-smi --query-gpu sample per interval over the devices of simulation.gpu_list (every device when the list is empty) (utilization, memory utilization, memory used, power, temperature; mean, sum, or maximum over devices). The summary adds peak_rss_mib, mean_cores_busy, peak_cores_busy, peak_load_1min, and the GPU means and peaks when GPU samples exist. Sampling is Linux-only; a failing nvidia-smi disables GPU sampling for the rest of the run after one warning, and a sampler failure never aborts the run.

The backend's own performance report is captured as well. The last timing table it prints to stdout (one per DTADJ, cumulative CPU seconds per code section: regular and irregular force, prediction, KS, adjust, output, communication, …) becomes the [telemetry.backend_timing] sub-table with lower-case keys (total, reg, irr, ks, reg_gpu_s, …), and the Perf.(Gflops) lines of the AVX/SSE or GPU regular-force profiles on stderr are summarised as [telemetry.force_kernel_gflops] (samples, mean, peak).

Cost estimate at launch

With [cost] enabled = true (the default) every engine launch, first segment or restart, is preceded by an estimate: estimate_cost reads N, NNBOPT, TCRIT, DTADJ and DELTAT from the input file (a restart passes the remaining span), takes the rate in seconds per N-body time unit from the table at that N (cost_rate: log–log interpolation between the rows, extrapolation with the exponent of the nearest segment; a two-cluster configuration is multiplied by merger_factor), and derives the wall time, the number of segments the wall budget implies (wall_s / (wall_budget − stop_margin), rounded up) and the disk the run will take: the restart dumps (one per adjustment unless checkpoint_keep bounds them, at the size _checkpoint_dump_bytes gives), the conf.3 snapshots (40 bytes per body per output) and the stellar and binary text outputs (about 130 bytes per star per output). The estimate is logged and written into the segment record (cost_wall_s, cost_segments, cost_disk_bytes, cost_rate_s_per_nb, cost_basis). When budget_hours > 0 and the wall time exceeds it, the launch warns or, with on_exceed = "refuse", raises an ArgumentError before anything is written.

The built-in table is the September 2026 measurement of the GPU build on one NVIDIA H200 NVL with 8 host threads, single King cluster at rest (bench/gpu_cells.jl, bench/gpu_scaling.jl): 64 s per unit at N = 10⁵ (over 0.25 units, start-up included: an upper bound), 281 s at 5×10⁵ and 1087 s at 10⁶ (2.0 units each). The two-cluster cells cost 1.85–1.99 times the single cell at equal N, hence the merger factor. Thread count changes the rate by less than 15 % and is not modelled. Replace the rows through [cost] table once your own device has been measured; a one-row table is refused because nothing can be interpolated from it.

Batch jobs under Slurm

A run longer than the queue's time limit is a chain of engine segments, one job each: the first job starts the pipeline, every later one resumes it (Resuming and restarting a run), and the job that reaches the end time post-processes and draws the figures. With [cluster] enabled = true:

julia scripts/run_cluster.jl config.toml                # submit the chain
julia scripts/run_cluster.jl config.toml --dry-run      # render the job script and the submission commands only

submit_run fixes the run id (--run-id=<id> or generated as run_pipeline would), creates <runs_dir>/<run_id>/cluster/ with the frozen configuration (config.toml, absolute paths) and the generated job script job.sbatch, and submits. The script is generated at submission from the [cluster] keys: the #SBATCH lines (job name, partition, account, qos, nodes, tasks, CPUs, memory, gres, exclusive, time limit, the extra options), --signal=B:TERM@<stop_margin>, --output=<run_dir>/cluster/slurm_%j.out, the prologue lines, JULIA_NUM_THREADS, and exec julia scripts/run_cluster_segment.jl <run_dir>. The exec makes the Julia driver the batch-step process, so the scheduler's signal before the limit reaches the driver, whose exit hook stops the engine with a dump; a job-wide SIGTERM (scancel) is answered by the launch script (Wall budget and stop requests). The wall budget stays the normal path: simulation.wall_budget is required, and wall_budget + stop_margin + overhead must fit time_limit, which in turn must not exceed partition_limit when that is given; a configuration that does not fit is refused by load_config.

Two chain modes. chain = "resubmit" submits one job; at the end of its segment the job submits its successor with --dependency=afterany on itself while the run is short of its end time and below max_segments (0 = no cap), so the chain grows as needed and a run that completes early submits nothing further. chain = "dependency" submits max_segments jobs at once, each --dependency=afterok on the one before (--kill-on-invalid-dep=yes); a run that completes earlier leaves the remaining jobs to exit at once with nothing to do. A run halted by the engine's energy check, terminated by the start-up watchdog or stopped by the stall watchdog ends the chain in both modes, since a resume would refuse it. A resubmit chain also stops after a segment that ended failed or killed without progress, or after the second failed segment in a row, with a warning and a chain_stopped row in the ledgers.

Inside the job, cluster_segment(run_dir) runs the segment (run_pipeline on the first job, resume_pipeline afterwards), keeps scontrol show jobid -dd of the job in cluster/job_<id>.txt, and appends to the ledgers: cluster/jobs.csv in the run directory and cluster_jobs.csv in runs_dir, one row per event (submitted, started, ended, chain_stopped) with the time, run id, job id, the job it depends on, the segment count, the run status, the host and a note (the submission command, or the reason of a stop). read_job_ledger reads either as a Vector of NamedTuples with nine String fields. The segment records of RUN_INFO.toml carry the job id as well (slurm_job_id). A dry run writes the script and prints the submission commands with placeholders for the job ids, and writes no ledger row.

On a Slurm GPU node the keys typically read partition = "GPU", gres = "gpu:1", cpus_per_task = 8, mem = "64G", sbatch_options = ["--hint=nomultithread"], with a prologue that sets the Julia depot and puts the CUDA toolkit on PATH; input_files/gpu/gpu_single_600k.toml carries such a block, disabled.

8. Parameter sweeps

A sweep runs the merger pipeline over a Cartesian grid of merger-TOML values times a set of seeds, one directory per point:

[sweep]
name = "demo"                              # letters, digits, "_", "-"
pipeline_config = "../config.toml"         # base pipeline config, relative to this file
merger_config = "merger_demo_small.toml"   # base merger config, relative to this file
seeds = [11, 12]                           # merger.seed at every grid point; distinct integers
concurrency = 5                            # simultaneous jobs; ≥ 1
omp_threads = 4                            # OpenMP threads per job; ≥ 1
runs_dir = "../runs"                       # sweep root: runs_dir/sweep_<name>_<timestamp>/
poll_interval = 2.0                        # seconds between job checks; > 0
controls = false                           # isolated single-cluster control companion per point
devices = []                               # CUDA devices the points are distributed over; [] = none; requires build.enable_gpu
engines_per_device = 1                     # engines admitted on one device at a time; ≥ 1

[sweep.grid]                               # dotted merger-TOML keys → arrays; Cartesian product
"merger.orbit.eccentricity" = [0.0, 0.6]
"merger.cluster2.N" = [500, 1000]
julia scripts/run_sweep.jl input_files/sweeps/sweep_demo.toml            # run
julia scripts/run_sweep.jl input_files/sweeps/sweep_demo.toml --dry-run  # prepare only

Axes address the merger TOML from its root; the parent table must exist in the base file (add [merger.tidal] with kz14 = 0 to sweep the tidal field), and merger.seed is reserved for seeds. Axes are processed in key order with the first varying fastest; point directories read <index>_<axis>=<value>_…_seed=<seed>.

prepare_sweep writes each point's merger.toml and config.toml (the base pipeline config with the install phase disabled, an absolute backend path, the point directory as run root, the derived merger file and the sweep's omp_threads) and loads both back through the regular parsers, so an invalid point fails before anything runs. run_sweep then executes the points as separate worker processes (run_sweep_point, at most concurrency at a time, each logging to <point>/sweep_point.log, the run itself in <point>/run/), rewrites sweep_index.toml on every state change (pending, running, done, failed with exit status and elapsed time; a point counts as done only when its run completed, and the ensembles use completed runs only), and writes sweep_summary.csv: index, id, seed, the axis values, status, elapsed time, exit status, and the final time, star count, pair count, energy error and virial ratio from the last ADJUST record. sweep_figures draws the half-mass Lagrangian radius and |ΔE/E| of every completed run on common physical axes, coloured by the value of one grid axis (the first by default; seeds share the colour), into <sweep>/plots with the base config's [visualization] settings. Four threads per job saturate the backend for N ≲ 2×10⁴ on the reference workstation, so five concurrent four-thread jobs use it fully.

On a GPU node the engine is host-bound (device utilisation of 14–33 % at the largest N measured), so several engines share one device. With devices = [0, 1] and engines_per_device = k the launcher assigns each point, when it starts, the device with the fewest engines running (ties to the lowest index), writes simulation.gpu_list = [device] into the point's frozen config.toml, and admits at most k engines per device in addition to the concurrency cap; the index statuses and the summary carry the device column (-1 without device assignment). The base pipeline config must set build.enable_gpu = true, since the CPU binary ignores GPU_LIST. The device indices are those of nvidia-smi (Choosing the GPU devices).

A sweep without [sweep.grid] is a seed ensemble of the base merger configuration (points 001_seed=11, …). Whenever a sweep has more than one seed, sweep_ensembles groups the completed points by grid values and ensemble_statistics interpolates every member's series onto a common time grid (the interval covered by all members) and takes the median and the central 68 % and 95 % intervals per node (type-7 quantiles). plot_sweep_ensemble draws the median line with the two bands for :lagrangian, :energy, :n_stars or :n_pairs, one colour per value of the chosen axis with the other axes held at fixed values (their first value by default, annotated); sweep_figures adds the Lagrangian-radius and energy-error ensembles automatically.

With controls = true every point gets a companion <index>_…_control whose merger TOML is the isolated equivalent of the point's configuration (control_merger_dict): one cluster at rest with the summed N, the N-weighted mean half-mass radius, and cluster 1's model, IMF and binary population, with the nbody6, stellar and tidal sections kept verbatim; intervals given in Myr (tcrit_myr, dtadj_myr, deltat_myr, dtplot_myr) carry over unchanged, and intervals given in N-body units (tcrit, dtadj, deltat, dtplot) are multiplied by (RBAR_est / r_h,control)^{3/2} so the control spans about the merger's physical time. The index and summary carry kind and control_of; the comparison and ensemble figures use the merger points only, and plot_control_comparison draws every merger (solid) against its control (dashed). write_control_merger_config derives a control file from any merger TOML outside a sweep; the control is a single-mode configuration (orbit_mode = "single").

9. Post-processing

Snapshots (conf.3, Fortran binary)

snap = read_conf3("path/to/conf.3_0")
snap.header        # SnapshotHeader with AS(1:20) parameters
snap.pos           # 3 × N matrix (Float32)
snap.vel           # 3 × N matrix (Float32)
snap.mass          # N-element vector (Float32)
snap.name          # particle identifiers (Int32)
snap.npairs        # regularised pairs; their components are stars 1:2npairs
snap.pair_name     # names of the pairs' centre-of-mass entries (negative: hierarchy)
pair_indices(snap) # [(1, 2), (3, 4), …], one tuple per pair

snaps = read_all_conf3(run_out, "conf.3_*")              # ordered by the time suffix
snaps = read_all_conf3(run_out; threaded = true)         # chunked over Threads.@spawn
snap.rho, snap.phi # local density / potential (empty if unavailable)
nparticles(snap)

The reader auto-detects the bulk-array format (one record with AS params + all particle arrays) and the legacy per-particle record format (32- or 44-byte records; the extended form carries rho/phi). Corrupt files are skipped with a warning. The engine writes NTOT = N + NPAIRS entries: the N stars, the components of regularised pair k at positions 2k − 1 and 2k, followed by one centre-of-mass entry per pair carrying the pair's mass. The reader keeps the N stars and drops the centre-of-mass entries, so that sums over a snapshot count every star once; snap.header.ntot remains the engine's NTOT. The centre-of-mass body of an active chain regularisation (NAME = 0), which the engine leaves among the stars beside the chain members, is dropped as well. For a hierarchical merger (negative pair_name) stars 2k − 1 and 2k are an inner-binary component and the outer body, not a pair.

Snapshot integrals and bound sets

Every energetic quantity of a snapshot uses the exact Newtonian potential, pair_potential ($Φ_i = −Σ_j m_j/r_{ij}$, G = 1, no softening, Float64), an O(N²) sum written as one KernelAbstractions kernel and run on the CPU threads of the session; a subset form gives the potential at given points of given sources, which updates a potential by subtraction when bodies leave a set. The engine's own phi column is not used: it is single precision, excludes a regularised component's companion and is zero for the ghosts of hierarchical systems.

Regularised pairs enter the energetics as their centres of mass (reduce_pairs, SystemSet). With the companion's potential included, a component's internal binding outweighs the energy of the pair's centre of mass, so a hard pair that escapes would otherwise stay bound. The stars of a hierarchical merger (negative pair_name) stay single.

bound_set selects the self-bound subset by iterative energetic unbinding: at every pass the reference velocity is the mass-weighted mean velocity of the current set and the systems with $½|V − v_\mathrm{ref}|² + Φ ≥ 0$ are removed, the survivors' potential being updated by subtracting the removed systems' contribution. The iteration stops when a pass removes nothing (status = :converged); bound_max_passes and bound_min_members end it otherwise (:pass_limit, with a warning, or :dissolved). The result carries the bound stars, the pass count, the reference velocity and the bound set's T and W. On a subset of a snapshot (one initial cluster) a pair with one component outside the subset is left out and listed in excluded.

b = bound_set(snap)                      # whole snapshot, pairs reduced
b = bound_set(snap, idx; max_passes = 200)
s = snapshot_integrals(snap)             # SnapshotIntegrals
write_snapshot_integrals("snapshot_integrals.csv", snapshot_integrals(snaps))

snapshot_integrals gives, per snapshot and in the engine frame: mass, centre of mass and its velocity, linear momentum, angular momentum about the origin and about the centre of mass, the stars' kinetic energy, the kinetic and potential energy of the reduced system (the engine's EKIN and −POT of the ADJUST line), the internal energy of the regularised pairs (EBIN), the potential energy of a linearised external field, tidal_potential ($−½ Σ m (T₁x² + T₃z²)$ over the stars, from the field TIDAL(1:4) passed as the tidal keyword, diag.tidal in the pipeline; zero without a field), and the bound set with its mass, energies and angular momentum. snapshot_integrals.csv adds L_removed = L(t₀) − L(t), the angular momentum carried off by escapers and stellar mass loss together, and writes the tidal term as w_tidal and the Jacobi integral as e_jacobi = e_total + w_tidal, equal to e_total without an external field. The snapshot positions are single precision, so the internal energy of the tightest pairs is resolved only to a few per cent; the centre-of-mass energetics agree with the engine's double-precision values to the four digits the ADJUST line prints.

Tidal runs. tidal_mode(diag) classifies the engine's external-field option KZ(14) of the options echo (:none when the capture lacks the echo). :none (0) is an isolated run. :linearised (1, 2) is a static field in the rotating frame. An engine built without the tidal-energy-total amendment never adds its potential energy to the total (the whole-system call of xtrnlv.F is commented out in energy.F): the ADJUST DE is then a drift, not an error, ETIDE prints as zero, the energy check halts a run with a tight QE, and the Jacobi integral e_jacobi of the snapshots is the conserved quantity. With the amendment in effect (source_amendments of the build record) ETIDE is evaluated at every adjustment and DE measures the error of the Jacobi integral. Under :orbit (3, 5) the engine accumulates the work of the field in ETIDE (regcor_gpu.F), so its DE is an error measure, while the snapshot energies are not comparable with the engine's total; the Milky-Way mode KZ(14) = 5 needs the fork from v2026.07-campaign.4, before which every escaper was charged the absolute Galactic potential and the run halted at its first energy check; :external (4) is neither. engine_energy_valid(mode) is true for :none and :orbit. The pipeline passes it to energy_intervals, so no interval is flagged under a linearised field, and logs the mode.

Estimators and their static test models

The estimators below take a particle set in N-body units (G = 1); the remnant diagnostics apply them to the bound set of every snapshot with the thresholds of the [postprocess] keys named in each paragraph. Each is checked against a static model whose answer is known (test/test_static_models.jl).

Centre. shrinking_sphere_centre(pos, mass) is the shrinking-sphere iteration of Power et al. (2003, DOI 10.1046/j.1365-8711.2003.05925.x): the centre is the centroid of the current set, the set is reduced by 2.5 % per step (shrink) to the particles closest to that centre, and the iteration stops at n_f = max(min(n_stop, ⌈stop_fraction N⌉), min(n_floor, ⌈N/2⌉)), that is at 1000 particles or 1 % of the set, whichever is smaller, with a floor of 500 particles or half the set. The centroid is number-weighted by default (weights = :number), because with a broad mass spectrum a mass-weighted centre locks onto the few massive stellar remnants instead of the stellar density maximum. The result carries the centre, the radius of the final set (distance to its farthest particle), n_final, and sigma = radius/√(5 n_eff), the per-axis standard error of the centroid of a uniform sphere, with n_eff = n_final under number weighting and (Σm)²/Σm² under mass weighting. sigma is a lower bound on the centre noise: in a flat core the fixed point of the iteration itself wanders by about sigma (a/R_f)², with a the scale radius of the core and R_f the final radius. The keys are centre_n_stop, centre_stop_fraction, centre_n_floor and centre_shrink.

Core radius. core_radius(pos, rho) returns the density-weighted centre and the core radius √(Σ ρ_i² |r_i − r_d|² / Σ ρ_i²) of Casertano & Hut (1985, DOI 10.1086/163485), the definition behind the engine's RC. For a Plummer sphere of scale radius a it gives √0.3 a ≈ 0.548 a with exact densities; with sixth-neighbour number densities the calibration table finds it unbiased from N ≈ 3×10⁴ on and 1–2 % high below, with sixth-neighbour mass densities and a Kroupa spectrum 1.5–3 % high with ten times the scatter. The remnant diagnostics evaluate it with two densities of rank k = density_neighbours: the mass density, the mass of the k − 1 nearest neighbours over the sphere reaching the k-th (the engine's density column when most of its entries are positive, otherwise local_density with weighting = :mass), written as r_core, and the number density (k − 1)/(4π r_k³/3) (weighting = :number), written as r_core_number. The number variant exists because the mass density of a star carries the masses of its few neighbours: for a Kroupa mass function its noise is about 180 % per star, while the number density, the proxy behind the engine's XNDBL, is free of the mass spectrum. rho_core is the largest local mass density among the bound members.

Lagrangian grid. lagrangian_grid(pos, mass, centre) returns the radii enclosing the 18 fractions of the engine's lagr.7, either of the mass (weights = :mass, N_eff = (Σm)²/Σm²) or of the particle count (weights = :number, N_eff = N). An entry is used only when f·N_eff ≥ n_min and (1 − f)·N_eff ≥ n_min, i.e. with at least n_min (lagr_n_min) effective particles on either side of the radius; the others are masked (masked, radius NaN). The 100 % radius is the maximum order statistic of the radial distribution and is never used. The enclosed fraction is binomial (Giersz & Heggie 1994, DOI 10.1093/mnras/268.1.257), so the noise of a radius is σ(ln r_f) = [(1 − f)/(f N_eff)]^{1/2} / (d ln M/d ln r) (sigma_log), the slope taken as the central difference between the nearest unmasked neighbouring fractions.

Profiles. radial_profile(pos, vel, mass, centre) returns a RadialProfile on two shell sets out to the radius enclosing 99 % of the mass. The kinematic shells are of equal membership, max(1, min(nbins, N_used ÷ n_min_sigma)) of them, so that the statistical error is the same in every shell. Each carries its member-median radius r, its density rho, the radial dispersion σ_r and the one-dimensional tangential dispersion per component σ_t (σ_t² = ½⟨|v_t − ⟨v_t⟩|²⟩), both about the shell's mean flow, the anisotropy β = 1 − σ_t²/σ_r², and the errors δσ/σ = (2(n − 1))^{−1/2} (sigma_err) and σ_β = (1 − β)(3/n)^{1/2} (beta_err). The dispersions need profile_n_min_sigma members and β needs profile_n_min_beta; about 300 members give β to ±0.1 near isotropy. The logarithmic density shells start from profile_nbins log-spaced edges and are merged outward until each holds at least profile_n_min_density members, with the mass-weighted mean radius r_log, the density rho_log and the membership n_log. The density and velocity-dispersion figures draw the kinematic shells (r, rho, sigma_r, sigma_t, beta); the logarithmic shells are not drawn.

Relaxation and crossing times. relaxation_times(pos, vel, mass, centre) returns the half-mass relaxation time t_rh = 0.138 N^{1/2} r_h^{3/2} / (m^{1/2} ln γN) (Spitzer 1987), with m = M/N, and, given the core density and the one-dimensional core dispersion, the core relaxation time t_rc = 0.338 σ_c³/(m ρ_c ln γN) (Giersz & Heggie 1994, DOI 10.1093/mnras/268.1.257). Both are given for the two factors of relaxation_gamma: γ = 0.11 is calibrated for equal masses (Giersz & Heggie 1994), γ ≈ 0.02 is adopted for a mass spectrum (Vesperini et al. 2013, DOI 10.1093/mnras/sts434), and neither is calibrated for a Kroupa spectrum with stellar remnants, so the pair brackets the uncertainty. The crossing time is t_cr = 2 r_h/σ_3D, with σ_3D² = Σ m |v − v̄|²/M about the mass-weighted mean velocity; the energy-based convention G M^{5/2}/(2|E|)^{3/2} differs from it by a factor of order unity. local_relaxation_time(rho, sigma_1d, m_mean, N, gamma) evaluates the same 0.338 form for a shell of a profile.

Mass segregation. mass_segregation(pos, mass; tracer, n_mst) compares the Euclidean minimum spanning tree (MST) of a tracer class with those of random sets of the same size. The remnant diagnostics fix the class by identity: the msr_n_tracer most massive stars of the first snapshot's bound set, followed by name through the run, since the most massive stars by present mass change identity as massive stars become remnants. At every snapshot the ratios are evaluated for each N_MST of msr_scan that the surviving tracers fill, against msr_n_random random sets, msr_n_random_small for N_MST ≤ msr_n_small, drawn with the seed msr_seed. Three ratios are reported: Λ_MSR, the mean length of the random trees over that of the tracer tree (Allison et al. 2009, DOI 10.1111/j.1365-2966.2009.14508.x); Λ̃_MSR, the same with the median edge length, insensitive to single long edges to outlying tracers (Maschberger & Clarke 2011, DOI 10.1111/j.1365-2966.2010.17602.x); and Γ_MSR, the ratio of geometric-mean edge lengths (Olczak, Spurzem & Henning 2011, DOI 10.1051/0004-6361/201015264). The headline values are those at N_MST = 20, or at the largest N_MST when 20 is not part of the scan. Without segregation Λ_MSR exceeds unity by more than its error in about one case in six, so a single 1σ excess is no detection; the segregation time is the first snapshot with Λ_MSR − σ > msr_threshold.

Coalescence. coalescence_time(snaps, cluster_ranges) reduces every initial cluster (tag of cluster_ranges) at every snapshot to its bound set, with the shrinking-sphere density centre of that set and its half-mass radius r_h about the centre; a cluster with fewer than 20 bound stars is absent at that snapshot. Two present clusters are merged when their centres are closer than min(r_h,i, r_h,j), and n_distinct counts the connected components of the merged pairs (union–find). The clusters have coalesced at the first snapshot from which a single group of at least two present clusters persists at every later snapshot, so a pericentre passage that separates again does not count (Fellhauer et al. 2002, DOI 10.1046/j.1365-8711.2002.05143.x). separation and threshold are the pair-by-snapshot matrices of the centre distances and of min(r_h,i, r_h,j), in the pair order (1, 2), (1, 3), …, (2, 3), …. The former criterion, member centres of mass closer than the sum of the initial RMS radii, was retired: the RMS radius of a Plummer sphere diverges logarithmically with the truncation radius, and the member centre of mass follows the stripped debris rather than the cluster.

Rotation. rotation_analysis(pos, vel, mass) takes the spin axis from the angular momentum L of the particles within 2 r_h of the shrinking-sphere centre, about their own mean velocity, so that loosely bound outer stars and tidal debris do not tilt it. The profile, a RotationProfile, uses cylindrical shells of equal membership, max(1, min(rotation_nbins_max, ⌊N_eff/rotation_n_min⌋)) of them with N_eff = (Σm)²/Σm². Each shell carries the mass-weighted mean azimuthal velocity v_rot, the dispersions sigma and sigma_phi, and the debiased amplitude sign(v̄_φ) [max(v̄_φ² − σ_φ²/n, 0)]^{1/2} (v_rot_debiased), which removes the noise bias of a mean of n azimuthal velocities. From the shells follow λ_R (Emsellem et al. 2007, DOI 10.1111/j.1365-2966.2007.11752.x) and, with the angular momentum and the energy of the whole set, the Peebles spin λ_P = |L| |E|^{1/2}/(G M^{5/2}) (Peebles 1969, DOI 10.1086/149876). The sign-flip null reverses the azimuthal velocity of every particle with probability ½ in rotation_n_null draws, keeping the shells, σ and E, and its rms values are the floors v_rot_floor, lambda_r_floor and lambda_peebles_floor (after Sollima, Baumgardt & Hilker 2019, DOI 10.1093/mnras/stz505); for uncorrelated signs the analytic floor of the Peebles spin is λ_P = 0.295/√N_eff. v_peak and r_peak fit the rotation curve V(R) = 2 V_pk (R/R_pk)/(1 + (R/R_pk)²) of Bianchini et al. (2018, DOI 10.1093/mnras/sty2225) to the shells within 3 r_h, weighted by membership.

Shape. shape_tensor(pos, centre) returns one ShapeShell per shell, the intrinsic axis ratios from the iterative shape tensor of Zemp et al. (2011, DOI 10.1088/0067-0049/197/2/30) with fixed semi-major axis. The shells are seeded at the radii enclosing 10 %, 50 % and 90 % of the particle count. At each iteration the members are the particles with elliptical radius (x_a² + x_b²/q² + x_c²/s²)^{1/2} inside the shell, the unweighted tensor S = (1/n) Σ x xᵀ of their positions is diagonalised, and its sorted eigenvalues a² ≥ b² ≥ c² give q = b/a ≥ s = c/a and the new frame, until both ratios change by less than 10⁻³. The tensor is unweighted because the r⁻²-weighted form biases the result towards rounder shapes (Allgood et al. 2006, DOI 10.1111/j.1365-2966.2006.10094.x). A shell with fewer than shape_n_min_shell members, or fewer than shape_n_min_enclosed particles inside its outer ellipsoid, returns q = s = NaN; a spherical sample of n members gives 1 − E[c/a] ∝ n^{−1/2}. projected_ellipticity(pos, centre, r_h) gives ε = 1 − (λ_min/λ_max)^{1/2} of the 2 × 2 second-moment matrix in the (x, y), (x, z) and (y, z) projections, within circular apertures at fractions of the half-mass radius (¼, ½ and 1 by default, after Gavagnin et al. 2016, DOI 10.1093/mnras/stw2064). The circular aperture truncates the major axis first, so the ε of an elongated system decreases towards large apertures.

Segregation and mixing measures. aplus(r_tracer, r_reference, r_h) is the area A⁺ = ∫ [φ_T(x) − φ_R(x)] dx between the cumulative radial distributions of a tracer and a reference population in x = log10(r/r_h) (Alessandrini et al. 2016, DOI 10.3847/0004-637X/833/2/252, in the r_h-normalised form of Lanzoni et al. 2016), positive when the tracer is more concentrated; integrated exactly, it equals ⟨x_R⟩ − ⟨x_T⟩, and its error is the jackknife standard deviation over the tracer sample. two_sample_d(x1, x2) is the two-sample Kolmogorov–Smirnov statistic D = sup |F₁ − F₂| with the null floor 0.87[(n₁ + n₂)/(n₁n₂)]^{1/2}, the asymptotic expectation of D for two samples of one distribution: the level an effect size is compared against, not a p-value. mixing(pos, vel, mass, tags, centre, r_h) applies both to two tagged populations within 2 r_h: A₂⁺ (Dalessandro et al. 2019, DOI 10.3847/1538-4357/ab45f7) and D of the radii, of the specific energies when given, and of the specific angular momenta about the mean velocity. Two populations can share a radial profile long before they share an energy distribution, which is why the test extends to the integrals of motion.

Snapshot binaries. local_density(pos, mass; k = 6, weighting) evaluates the Casertano–Hut density on a k-d tree in O(n log n), the same estimator as the serial O(N²) routine _local_density. snapshot_pairs(pos, vel, mass) returns SnapshotPair records: the candidates are the pairs in which one star is among the pair_k nearest neighbours of the other, the bound candidates are joined greedily in ascending specific orbital energy, most bound first, and a pair is accepted when neither star is already paired, so the first pairs accepted are mutually most bound and a star whose most-bound partner was taken can still pair with its next choice: one level of the node joining of Bate (2009a, DOI 10.1111/j.1365-2966.2008.14106.x), ordered by energy instead of separation; a triple appears as its inner pair. Two-body boundedness ignores the environment, so tidal_ok flags the pairs that satisfy a(1 + e) < pair_tidal_factor × r_third, r_third being the distance from the pair's centre of mass to the nearest other star. The hardness is x = E_b/kT (Heggie 1975, DOI 10.1093/mnras/173.3.729), with kT = 2K/(3N) from the kinetic energy K of the N members of the bound set in the remnant diagnostics. reconcile_pairs(pairs, snap) compares the result with the engine's KS pairs. The KS list is the hard-and-close subset of the binary population, since regularisation requires a separation below RMIN, so a census from it alone is biased: it misses the bound pairs wider than RMIN, which for massive primaries are themselves hard.

Angular-momentum budget and resolved rotation. angular_momentum_budget(snaps, bound_sets, units) follows the internal angular momentum of all stars, about their centre of mass and mean velocity, between consecutive snapshots, by name. The internal angular momentum is invariant under translations and boosts of the frame, so the engine's centre-of-mass corrections after escaper removals do not enter it. The stars absent from a snapshot carry off the difference between the internal angular momentum of the previous snapshot with and without them (l_removed), the stars new in a snapshot bring the same difference at that snapshot (l_added), and the stars common to both shed, with their mass loss, the difference between their internal angular momentum with the earlier and with the later masses, at either snapshot's phase space and averaged (l_stellar); the stars that became remnants in the interval (the engine's remnant_formation and kick_* events) are left out of that term and carry their own, l_remnant, the change of the common set's internal angular momentum they cause (natal kick and mass loss together); residual = l_total + l_removed − l_added + l_stellar − l_remnant − l_total(t₁) then vanishes exactly for removals, mass changes and kicks at fixed phase space of the other stars and otherwise measures the torque of the departing stars on the rest between the last snapshot that holds them and their removal, with the integration drift of an isolated run or the tidal torque of a run in an external field. The residual is judged against l_scale = Σ m |r − c| |v − v̄|, the angular-momentum content of the stars, since a configuration with little net rotation has |l_total| far below it. The spin axis of every snapshot is the unit angular momentum of the bound set about its centre of mass; λR and its sign-flip floor (`rotationanalysiswith that axis) are measured inside the Lagrangian radiir10,r50,r90of the bound set and for every initial-mass class (massclassedges, the class fixed by the mass of a star in the first snapshot where it appears), with the axial angular momentum of every class and its fraction of the bound set's. The time axis is also given in elapsed relaxation timesNrh = ∫dt/trh(trapezoid over the snapshots, the tworelaxationgammafactors), the clock on which an isolated system redistributes its rotation; the budget is the measurement that separates this redistribution from loss through escapers and stellar mass loss.angular_momentum.csv` carries one row per snapshot.

Equipartition mass. equipartition_fit(mass, vel) fits the dispersion–mass relation of Bianchini et al. (2016, DOI 10.1093/mnras/stw552), σ(m) = σ₀ exp(−m/2m_eq) for m ≤ m_eq and σ₀ e^{−1/2} (m/m_eq)^{−1/2} above, to the one-dimensional dispersions of equipartition_bin_width mass bins holding at least equipartition_n_min stars, by weighted least squares on a logarithmic grid of m_eq with the amplitude solved at every grid value; the Δχ² = 1 run around the minimum gives the interval, and a minimum at the top of the grid (100 times the heaviest bin) reports m_eq = Inf, no equipartition within the range of the sample. equipartition_series applies it per snapshot to the bound stars within the half-mass radius of the bound set, restricted to K* ≤ 9 by the nearest stellar-evolution snapshot when one lies within half the snapshot spacing (equipartition.csv).

Merger tree and progenitor budget. For a run with initial clusters, merger_tree(snaps, cluster_ranges; bound_sets) turns the pairwise density-centre separations and thresholds of coalescence_time into a tree: a pair is joined from the first snapshot after which it stays within the threshold (a pericentre passage that separates again does not count), the joins are processed in time order with union–find, and every join that connects two groups is a MergerEvent with the groups and the separation of the triggering pair; dissolved records the snapshot after which a cluster is never present again. progenitor_budget(snaps, cluster_ranges, bound_sets) gives, per snapshot and progenitor, the initial names' mass split exactly into the present mass, the mass removed with the stars that left (at their last mass) and the mass shed by stellar evolution, the bound members and mass inside the global bound set, the half-mass radius of the bound members about their own density centre and its offset from the global centre, and the mixing of the progenitor's bound members against the other bound stars within 2 r_h of the global centre (A₂⁺ with its jackknife error, the two-sample D on radius, specific energy when the snapshot carries potentials, and angular momentum, with the null floor). merger_tree.csv lists the events; progenitor_budget.csv one row per (snapshot, progenitor).

Binary spans. binary_spans(read_binary_events(log); listings, collisions, coalescences, nzero, nbin0, tstar_myr) follows every pair of component names through its KS regularisations. Consecutive episodes of a pair are one span when the gap between them is at most span_n_periods periods of the earlier episode, or a chain holding both components or a stable hierarchy with the pair as inner binary covers it, and no other regularised pair holds one of the components in between (an exchange ends the span). A span is primordial when its names are (2k − 1, 2k) with 2k ≤ 2 NBIN0 and it is regularised at the start, reformed when such a pair forms again; otherwise its origin is an exchange (an EXCHANGE or CHAIN BINARY line leaves it bound and a component was in another pair before) or dynamical, with the sublabel :gw_capture or :capture when a GR CAPTURE or tidal NEW CAPTURE line falls in its first episode and :three_body when it forms at the end of a chain. The end class takes logged ends first (GW merger: a coll.13 collision of the pair with a GR KSINT COLL or COLL DUE TO GW UNPERT trigger; stellar merger; collision; binary escape; exchange), then the inferred ones (supernova disruption after MDEND KSREG; :flyby for a pair opened and closed unbound, a hyperbolic encounter that never was a binary; disruption; unresolved), and :censored_run_end for a span open at the end of the log. The spans need the KS event lines of KZ(10) ≥ 2 (NEW and END KSREG; binary_physics = "full" sets it); without them the log holds no episodes. This is the level of the engine's own regularisation: a pair that leaves KS bound and is not regularised again within the join criteria ends as :unresolved. binary_spans.csv holds one row per span with the elements of its opening and closing records.

Bound spans. bound_pairs(snapshot) finds the physically bound pairs of a snapshot whatever the engine regularises: the pairs of the greedy joining by specific orbital energy of snapshot_pairs (Bate 2009a) whose apocentre perturbation by the four nearest other bodies stays below bound_gamma_max, those whose dominant perturber is the bound outer body of a triple stable by the Mardling & Aarseth (2001, DOI 10.1046/j.1365-8711.2001.03974.x) criterion (in the engine's form, stability.f), and every KS pair of the snapshot, whose single-precision state cannot resolve a hard pair. bound_spans(snapshots; nbin0) follows each pair of names over the snapshots; up to bound_n_miss consecutive snapshots in which the pair stays bound but fails the perturbation test are bridged, and formation and end are interval-censored to the snapshot cadence. bound_spans.csv has one row per span with its first and last member snapshot, the KS fraction, the elements at both ends and whether the end is a separation.

Binary census. binary_census(binary_spans, bound_spans; nbin0) joins, per pair, the overlapping or adjacent spans of the two levels — a bound span widened to the snapshots before its first and after its last member — into one CensusSpan with the limits and counts of each level; flybys (never bound) are left out. The origin comes from the earlier level (the level-E origin, or primordial for a primordial pair bound at the first snapshot), the end class from the later one (the level-E end class, or :separated, :censored_run_end, :unresolved from level P). With both span stages enabled the pipeline writes binary_census.csv.

Binary population series. binary_population_series(snapshots; radius_frame, edges, kstar, q_min, primary_window_msun) gives, at every snapshot and for both census levels, the binary fractions by systems, f_b = N_b/(N_s + N_b) with its binomial error, by stars, f_⋆, and by mass, f_M. Level :ks (E) takes the KS pairs of the snapshot, level :bound (P) the pairs of bound_pairs, whose stable-triple inner pairs count as binaries and their outer bodies as singles. A merged hierarchy (a KS slot with a negative centre-of-mass name) enters level E as its inner binary, the second inner component taken as the massive non-KS star nearest to the first, and its outer body as a single (n_hierarchies). The fractions are given over all radii (bin 0) and per shell about the shrinking-sphere centre, in enclosed mass fraction ("lagrangian", default edges 0, 0.1, 0.25, 0.5, 0.75, 0.9, 1) or in r/rh ("rh", default 0, 0.5, 1, 2, 4, ∞). With stellar types every row is repeated per class of `STELLARCLASSES: a binary counts in the class of its primary, whilef⋆andfMof a class count its members in any binary, whatever the partner. The q-restricted fractionfbqis the fraction of binaries with q >populationqminamong the systems whose single or primary mass lies in the windowpopulationm1min–populationm1max(0.47–0.76 M☉, the window of Milone et al. 2012, DOI 10.1051/0004-6361/201016384, which is set relative to the turn-off of old globular clusters); with stellar types only pairs of two main-sequence stars enter its numerator, as for a photometric binary. The stellar types come fromsev.83andbev.82(stellartypemap), matched to each snapshot by N-body time; when no epoch matches, the latest earlier epoch is taken and the largest lag logged. Bodies without a type, such as the outer body of a merged hierarchy and the body that represents a chain, count under:allonly; more than 1 % untyped massive stars indicates mismatched epochs and is refused.binary_population.csv` holds one row per snapshot, level, shell and class.

Gravitational-wave observables. The functions take masses in M☉ and semi-major axes in au. gw_inspiral_time(m1, m2, a, e) is the coalescence time [yr] of the orbit-averaged quadrupole radiation, T = T_c (1 − e²)^{7/2} F(e) with T_c = 5c⁵a⁴/(256 G³ m₁m₂M) and the time factor F (gw_time_factor) by quadrature (Peters 1964, DOI 10.1103/PhysRev.136.B1224); gw_inspiral_time_mandel is the fit of Mandel (2021, DOI 10.3847/2515-5172/ac2d35) to it. No post-Newtonian correction is applied: gw_zwick_factor returns the 1PN-recalibrated factor exp(2.5 r_S/p₀) of Zwick et al. (2020, DOI 10.1093/mnras/staa1314) separately, as a sensitivity measure. chirp_mass gives 𝓜 = (m₁m₂)^{3/5}/M^{1/5} [M☉], orbital_frequency the Keplerian f_orb [Hz]. gw_frequency(m1, m2, a, e; definition) [Hz] has three definitions that coincide at e = 0 and differ by large factors at high e: :f22, the dominant quadrupole harmonic 2 f_orb; :wen, the peak harmonic of Wen (2003, DOI 10.1086/378794); and :peri, the frequency of a circular orbit of the pericentre radius. eccentricity_at_frequency(m1, m2, a0, e0, f_ref; definition) follows the Peters track from the recorded elements to the reference frequency and returns the eccentricity, the semi-major axis and the time to get there, or NaN with above_at_record = true for a binary already above f_ref.

Core-collapse markers. core_collapse_markers(time, r_core, rho_core; window = 5) returns the index and time of the minimum of the core radius (t_rc_min) and of the maximum of the core density (t_rho_max), both after a running mean over window snapshots. The remnant diagnostics add two markers from the snapshot binary census: the first snapshot with hardness_max > 10 (t_first_10kt) and the first with hardness_max > 10 f_max (t_first_10fmax_kt). The markers generally fall at different snapshots (Tanikawa, Hut & Makino 2012, DOI 10.1016/j.newast.2011.09.001), so core collapse is reported as this set of times, never as one moment. With primordial binaries the two pair-based markers fire at the first snapshot and carry no information; they are meant for runs that start without pairs.

Static test models. Four routines give a model with a known answer for one estimator; the units are those of sample_plummer (G = 1, total mass 1, lengths in units of the scale radius). sample_plummer_om(N, a, r_a) samples the Osipkov–Merritt Plummer sphere (Merritt 1985, DOI 10.1086/113810), with the Plummer density and the anisotropy β(r) = r²/(r² + r_a²); its distribution function is non-negative for all bound orbits only when r_a ≥ 0.75 a, smaller values are refused, and r_a = Inf is the isotropic model. It tests the anisotropy profile of radial_profile. lynden_bell_flip!(vel, pos, axis, p) gives the azimuthal velocity about axis the positive sign with probability p (Lynden-Bell 1960, DOI 10.1093/mnras/120.3.204), which leaves the density and every dispersion unchanged and makes ⟨v_φ⟩ = (2p − 1)⟨|v_φ|⟩ in any shell; p = ½ is the non-rotating null, and the model tests rotation_analysis and its floors. stretch_positions!(pos, q, s) scales y by q and z by s, a static model with axis ratios b/a = q and c/a = s (not an equilibrium) that tests shape_tensor and projected_ellipticity. rank_masses_by_energy!(mass, energy, S) gives a random fraction S of the particles the largest masses, the most bound of them the largest (Šubr, Kroupa & Baumgardt 2008, DOI 10.1111/j.1365-2966.2008.13161.x), the remaining masses going to the other particles in random order; S = 0 is a random permutation, and the model tests mass_segregation.

Calibration table. scripts/calibrate_estimators.jl measures every estimator on six static models (the isotropic Plummer sphere, the Osipkov–Merritt sphere with r_a = 1.5 a, the fully prograde Lynden-Bell model, Plummer spheres with independent and with energy-ranked Kroupa masses, and the stretched sphere with q = 0.8, s = 0.6) over N = 10³ … 10⁶ with 64 to 4 replicas per point, every realisation seeded by StableRNG(10⁸ i_model + 100 N + replica), so the table regenerates identically anywhere (julia -t 6 scripts/calibrate_estimators.jl, about 20 minutes; --quick for a schema check). assets/calibration/estimators.csv holds one row per (model, estimator, quantity, N): the known answer (truth, NaN without one), the mean and scatter over the replicas, bias = mean − truth with bias_err = scatter/√n_rep, the mean of the estimator's own error estimate (reported_error) and of the analytic noise prediction (predicted_scatter); estimators.toml records the version, the grid, the replicas and the timings. The table is the reference the validity record of a run reads for the finite-N bias and noise of each estimator. Its first version establishes, among others, that the shrinking-sphere centre scatters by about 0.06 a at every N in a Plummer core (the fixed point of the iteration does not tighten with N, so the centroid noise is a lower bound), that the Lagrangian radii carry exactly the binomial noise, that the density of a logarithmic shell at its member-median radius is 7–8 % below the model (a binning effect, independent of N), that the sign-flip floors of λ_R match the realised null, and that the pair finder reports about 18 spurious soft pairs per snapshot at every N and no hard tidally stable one.

Validity record

validity_record(results, settings) condenses the products of a post-processed run into what a comparison of runs needs to know before it uses them; the pipeline writes it as validity.toml and validity_snapshots.csv beside the other products (validity = true). The thresholds are configuration keys, fixed before the physical outcomes are looked at, and are recorded in the file. The sections of validity.toml:

  • header: run id, package version, engine commit and source amendments of the build record, calibration version and model (plummer for equal masses, plummer_kroupa otherwise), tidal mode, initial star count and time span.
  • energy: per-interval relative energy changes of the ADJUST records (largest, median, the number above validity_interval_de), the intervals flagged by energy_intervals, the largest change without the pair-binding channel d_ebin (so that one hard binary does not dominate), the cumulative |DETOT/E₀| against validity_cumulative_de, the energy-budget residuals, and a verdict: ok, flag (with reasons), unavailable, or not_applicable when the engine's DE is not an error measure (a linearised tide without the tidal-energy correction).
  • mass, angular_momentum: the residuals of the mass and angular-momentum budgets (the latter over l_scale).
  • bound_set: how many bound sets converged, hit the pass limit or dissolved.
  • capacity: the fixed-size engine arrays the run came close to. The SIMD irregular-force library is opened for N + NBIN0 − NPAIRS + 100 bodies at each start or restart and indexed without a bounds check, so KS pairs beyond NBIN0 + 100 overrun it: simd_headroom = 100 − (max NPAIRS − NBIN0), NBIN0 from the engine's &INDATA echo. The merger table of stable hierarchies holds MMAX − 1 entries (MMAX from engine_limits of the build record): merge_table_headroom. The verdict is flag when either is exhausted, with the reasons.
  • cadence: snapshot spacing against the crossing time of the bound set (Heggie & Mathieu 1986: t_cr = M^{5/2}/(−2E)^{3/2}, 2√2 in standard units) and the initial half-mass relaxation time; whether core-collapse markers are resolved (spacing ≤ 0.1 t_rh); the time resolution of the coalescence.
  • stages: the end of violent relaxation (validity_settle_tcr crossing times), the pericentres (interior minima of the per-pair density-centre separations of remnant_diagnostics before coalescence), the coalescence time, and the times from which the remnant is virialised (|2T/|W| − 1| ≤ validity_virial_tolerance from then on; the drift of ln r_10 of lagr.7 per crossing time and its stationarity are reported beside it, since stellar mass loss and relaxation move the inner radii of a virialised cluster), kinematically relaxed (λR stationary within the larger of `validityratetoleranceand twice its sign-flip floor) and mixed (|A₂⁺| ≤ 2σfor every progenitor), eachreached,notreachedorundetermined, also in initial relaxation times. A stationary series changes by at most the tolerance over every window ofvaliditywindowtcr` crossing times. These are single-run proxies of the completion criteria of the literature, which measure stationarity against the seed scatter; the ensemble stage replaces the tolerance by that scatter.
  • calibration: bias, scatter and error ratio of the tracked estimators (number-density core radius, ln r at 10 % and 50 %, λR, the middle-shell axis ratio, A₂⁺, the centre offset) at the bound star count, interpolated in log N in the calibration table, relative to the true value where it is finite and nonzero; ok is false where the relative bias exceeds `validitybias_tolerance`.
  • masks: the masking rules M1–M7 the estimators apply, with their thresholds.
  • [[epochs]]: time intervals with a kind and a description: the windows that exclude snapshots from the equilibrium estimators (violent_relaxation; pericentre, ± validity_pericentre_tcr crossing times of the denser progenitor, 2 r_h/σ with σ² = 0.4 m/r_h after Spitzer 1987; coalescence_phase, from the first pericentre window to coalescence, or the whole approach when the snapshots resolve no pericentre, which cadence.pericentre_resolved states) and the intervals with a flagged energy change, a mass-budget residual or an unconverged bound set.

validity_snapshots.csv has one row per snapshot: bound star count and its effective number (Σm)²/Σm², crossing time, 2T/|W|, the mass-fraction range a Lagrangian radius resolves (lagr_n_min / n_eff to 1 − lagr_n_min / n_eff), bound-set convergence, whether the snapshot lies in a window, equilibrium_ok, and bias, scatter and ok of every tracked estimator at the snapshot's bound star count. load_calibration() reads the shipped table and calibrated(cal, model, estimator, quantity, n) interpolates one entry.

Each ADJUST epoch is merged from up to three stdout lines (ADJUST:, RMIN/RSCALE, TIME[NB]); both positional and key-value ADJUST formats are handled, and particle counts are forward-filled across epochs where TIME[NB] lines are sparse.

Three energy fields are kept per adjustment. de_rel is the engine's DE, the energy change of the interval divided by max(T, |E|); de_abs is DELTA, the same change in N-body energy units; detot is DETOT, the engine's running sum of those changes, an absolute energy and not a relative error. The running sum of de_rel is what the engine calls ERRTOT and prints only at END RUN; cumulative_energy_error rebuilds it per adjustment, and read_energy_totals returns the engine's own totals for comparison.

The key-value ADJUST line also prints the energy terms EKIN, POT and ETIDE and the engine's correction channels EBIN, EMERGE, ESUB, ECOLL, EMDOT and ECDOT; AdjustRecord keeps them in N-body units (NaN on a positional line). The options echo gives diag.kz, the 50 KZ values (empty when the capture lacks the echo), and the TIDAL PARAMETERS echo gives diag.tidal, TIDAL(1:4) in N-body units, zeros without a linearised field.

Energy-jump localisation

a = energy_intervals(diag, events; engine_energy_valid = engine_energy_valid(tidal_mode(diag)))
energy_events_summary(a)
write_energy_intervals("energy_intervals.csv", a)
write_engine_events("engine_events.csv", a.events)

energy_intervals(diag, events; threshold, sigma, engine_energy_valid) splits the run into its adjustment intervals and returns an EnergyEventAnalysis with one EnergyInterval per interval (t_{k−1}, t_k], k ≥ 2: the engine's DE and DELTA of the ADJUST record that ends it, the increments of the six correction channels EBIN, EMERGE, ESUB, ECOLL, EMDOT and ECDOT over the interval (NaN when either end lacks the term), and the counts of the events the log places in it, per kind and in total. An interval is flagged when

\[|\mathrm{DE}| \ge \max\left(\mathrm{threshold},\; \mathrm{sigma} \times 1.4826 \times \mathrm{MAD}\right),\]

the median absolute deviation taken over the finite DE of all intervals of the run; score is |DE| over the robust scale 1.4826 × MAD. Each of the two bounds covers a case the other misses: the floor keeps a run whose errors sit at round-off level unflagged, and the robust scale keeps the rule relative to the run's own noise, so a few large jumps neither inflate it nor hide each other. With engine_energy_valid = false no interval is flagged (see Tidal runs under Snapshot integrals and bound sets).

Attribution is by co-occurrence: a flagged interval is set against the events and the channel increments it contains. One flagged with neither an event nor a channel increment is an integration error the log does not explain; energy_events_summary says how many there are, together with the number of intervals and of flagged ones, the flagging level, the robust scale, and the event counts of the flagged intervals by kind.

With [postprocess] energy_events the pipeline runs the localisation with threshold = energy_jump_threshold and sigma = energy_jump_sigma and writes two CSV products into the run directory. energy_intervals.csv has one row per interval with index, t_start, t_end, de_rel, de_abs, d_ebin … d_ecdot, score, flagged, n_events and one n_<kind> column per kind; engine_events.csv one row per event with the fields of EngineEvent (a stellar type the line does not carry and non-finite values as empty cells). Existing files are backed up, never overwritten.

Mass and energy budgets

rows = mass_budget(ints, escapers, counters, events, extract_scaling(diag))
mass_budget_summary(rows)
write_mass_budget("mass_budget.csv", rows)

mass_budget(ints, escapers, counters, events, units) returns one MassBudgetRow per snapshot, in N-body mass units: m_snapshot, the stars' mass; m_escaped, the escapers removed at or before the snapshot time (esc.11, binary escapers as their centre of mass); m_lost_stellar, the stellar-evolution loss ZMDOT of the last event.35 row at or before it; m_lost_collision, the collision and coalescence loss, the DM of the NEW STAR and COAL lines, which the engine takes from the cluster mass but not from ZMDOT; m_engine, the engine's own total mass after the last escape at or before the snapshot; and residual = m0 − (m_snapshot + m_escaped + m_lost_stellar + m_lost_collision) against the first snapshot's mass m0, with residual_rel = residual / m0. Two orderings in the engine make the identity exact: escapers are removed before the output of the same adjustment, and event.35 is written before the snapshot of the same output.

The identity misses the mass lost in Roche-lobe overflow and common-envelope evolution (roche.f, under KZ(19) ≥ 3), which the engine takes from the cluster mass without a stamped line. The counters nroche and nce of event.35 locate such steps; in the binary showcase run the loss is 5 × 10⁻⁷ of the mass, at its one common-envelope event. The Myr stamps of esc.11 and event.35 are converted with T* and the masses with M*, so the budget needs the stdout capture; a Myr-stamped record enters a snapshot's budget within a relative time_tolerance (default 10⁻⁵), which absorbs the six-digit rounding of the stamps. mass_budget.csv has the columns time_nb, time_myr, n_stars, m_snapshot, m_escaped, m_lost_stellar, m_lost_collision, m_engine, residual, residual_rel.

erows = energy_budget(ints, escapers, counters, diag, extract_scaling(diag); bevs = bevs)
energy_budget_summary(erows)
write_energy_budget("energy_budget.csv", erows)

energy_budget(ints, escapers, counters, diag, units; bevs) returns one EnergyBudgetRow per snapshot. The Jacobi integral of the snapshot (e_snapshot, the e_jacobi of the snapshot integrals), plus the energy the engine subtracted for the removed escapers (e_escaped), plus the engine's ECOLL + EMDOT + ECDOT (e_channels), is the total the engine conserves, e_total. With a counters file both come from the last event.35 row at or before the snapshot, at full precision: the escaper energy is ESESC + EBESC + EMESC (source = counters). Without one the escaper energy is the sum of m × EESC over esc.11, which misses the internal energy of escaping pairs, and the channels come from the last ADJUST record at or before the snapshot, whose four printed digits bound the closure once the kick energies exceed the total by orders of magnitude (source = escapers, or none without either file). ESUB and EMERGE are not added: chain members and the stars of hierarchies appear in the snapshot with their physical coordinates, so their binding energy is inside the snapshot sums. e_pairs, the regularised pairs' internal energy inside e_snapshot, is taken from bev.82 at the snapshot times it covers (pair_source = bev, the engine's double-precision elements, converted with M* V*²) and from the single-precision snapshot otherwise (snapshot, where the tightest pairs are quantised). residual is the change of e_total since the first snapshot and residual_rel that change over |E0|, the magnitude of the first snapshot's total; detot is the engine's own cumulative energy change DETOT at the last ADJUST record at or before the snapshot, which the residual tracks when the reconstruction is exact. energy_budget.csv has the columns time_nb, time_myr, e_snapshot, e_pairs, e_escaped, e_channels, e_total, residual, residual_rel, detot, source, pair_source.

10. Visualisation

The figure backend is an extension

Every figure routine — plot_*, animate_*, generate_plots, sweep_figures, remnant_figures, publication_theme — lives in the package extension Nbody6DynamicsMakieExt, which Julia loads as soon as a Makie backend is in the session:

using CairoMakie
using Nbody6Dynamics

The package itself declares no plotting dependency. A headless host therefore never fetches or precompiles Cairo, Pango, GLib, HarfBuzz or the font artifacts: initial conditions, engine build, integration, readers, diagnostics, sweeps and benchmarks are all backend-free. The distinction matters on a compute server whose system GLib is older than the artifact one: there the plotting stack is what fails to load, and the numerical work is unaffected by it.

Consequences to know:

  • Without a backend a figure routine has no methods: the call is a MethodError whose message names the routine and the remedy (using CairoMakie). The orchestration entry points below throw PlottingUnavailable before doing any work.
  • run_pipeline with [visualization] enabled = true, run_merger_pipeline(...; make_plots = true) and postprocess_external(...; make_plots = true) check for the backend before doing any work, so a missing backend costs nothing instead of costing an integration. Set the flag to false for a numerics-only run.
  • plotting_available() reports whether the extension is loaded.
  • The entry scripts under scripts/ run in their own environment (scripts/Project.toml) which carries the backend, so julia scripts/run_setup.jl config.toml plots as before. The benchmark environment carries no backend; the figure script bench/gpu_cells_figures.jl borrows the scripts environment.
  • A sweep worker inherits the driver's environment and loads the backend only if the driver has one, so sweeps behave like the session that launched them.

Every figure routine draws inside with_theme(publication_theme()): the session's theme is neither needed nor changed, and publication_theme() returns the theme as a value for scoping your own Makie code the same way. The theme is built at call time so that its Computer Modern faces come from MathTeXEngine's live registry: a face captured while the package precompiles carries a null FreeType pointer, and Makie would then render every plain-text label in its default sans font without warning.

Theme rules

  • No plot titles — contextual information (time, projection label, orbit parameters) is placed as in-axis annotations at the top-left corner
  • No minor ticks; major ticks face inward; fully boxed axes
  • Grid: dashed grey at very low opacity — on line plots only. Dense scatter plots (cluster projections, HR diagrams) disable the grid locally
  • Fonts: Computer Modern (NewComputerModern, bundled with MathTeXEngine) for text and math
  • Never-overwrite policy: before saving, any existing file at the target path is moved to the first free name#k.ext sibling (DrWatson-safesave style); this applies to plots, animations, dat.10, merger.inp, and metadata files alike
  • Legends appear only when ≥ 2 items are plotted; axis limits snap to nice round values with a visual buffer

Multi-panel montages (snapshot_evolution_*, hr_evolution) are one column wide like every other figure: the panels share the preset width (a shared colorbar column is taken from the panel area), use three ticks per axis, keep a data-free band above the data for the in-axis time annotation (a surface-density map fills its panel and carries the annotation in white in its top-right corner, clear of the tick marks), and scale their markers with the panel width; inner tick labels are hidden and the panel gap is compact unless the adaptive zoom shows every panel's ticks. A three-column grid at the single preset has 25 mm panels, so double is the preset for montages placed in a manuscript.

Stellar classes

Figures and the census group the types as the engine does for its per-type Lagrangian radii (STELLAR_CLASSES): pre-main sequence (−1), main sequence (0–1), Hertzsprung gap (2), red giant (3), core He burning (4), AGB (5–6), He star (7–9), white dwarf (10–12), neutron star (13), black hole (14), massless remnant (15). The last three have no photosphere that places them on the optical HR plane; they are counted, not drawn.

stellar_census(sevs, bevs) counts the stars of every class at every epoch, single stars (sev.83) and members of KS-regularised pairs (bev.82) separately. A star moves between the two files whenever its pair enters or leaves regularisation, so either file alone gives a population that changes for reasons unrelated to stellar evolution; in a run with primordial binaries a fifth of the stars can be in bev.82 at any time. run_pipeline writes the census to stellar_census.csv in the run directory, with or without a plotting backend.

13. N-body Units and Conversions

Nbody6++ works in N-body units with G = 1 and M_total = 1. When the engine builds the initial model itself, or reads a King model (KZ(22) < 2 or KZ(22) ≥ 6), it rescales to Hénon units (Hénon, 1971), E_total = -1/4, which makes the virial radius the unit of length. Nbody6Dynamics writes dat.10 with KZ(22) = 2, which the engine reads without rescaling: the unit of length RBAR is the half-mass radius of the whole initial configuration, and E_total differs from -1/4. An isolated King W₀ = 6 cluster starts near E_total = -0.20 (r_V ≈ 1.25 r_h); a bound pair starts lower, its orbital binding energy adding to the total. The virial ratio is Q = T/|W| with equilibrium at Q = 0.5.

Physical conversions come from the scaling factors printed in the PHYSICAL SCALING stdout block and collected into a UnitScaling:

FieldStdout symbolConvertsPhysical unit
rbarR*NB length → parsecspc
zmbarM*NB mass → solar massesM☉
tscaleT*NB time → megayearsMyr
vstarV*NB velocity → km/skm/s
ZMBAR is the total-mass scale, not the mean mass

Nbody6++ redefines ZMBAR at startup (start.F) as the total-mass scale factor — 1 NB mass unit (the whole cluster) = zmbar M☉ — and units.f converts masses as ZMBAR*M. The mean stellar mass is printed separately as <M> in the PHYSICAL SCALING line. extract_scaling therefore reads M*, not <M>.

units = extract_scaling(diag)
r_pc  = r_nb * units.rbar
t_myr = t_nb * units.tscale
v_kms = v_nb * units.vstar
m_sun = m_nb * units.zmbar

The same factors are available per snapshot from the conf.3 header via the accessors rbar(h), zmbar(h), tscale(h), vstar(h), plus time_nb(h), time_myr(h), rscale(h) (half-mass radius, NB), and rc(h) (core radius, NB).

14. Troubleshooting

Build fails with "hdf5.mod not found"

Fedora: the h5pfc wrapper likely has a broken includedir; see Build Phase Details. Ubuntu: ensure libhdf5-dev (or libhdf5-openmpi-dev with MPI) is installed.

Run never advances past t = 0

On an upstream build the engine prints the t = 0 adjustment, then sits at 100 % of one core forever; the start-up watchdog ends it. My fork bounds the digit count from v2026.07-campaign.3 on, so the default engine is not affected. The cause is the upstream string_left.f, which counts the decimal digits of DELTAT, DTADJ and DTPLOT by multiplying by ten until the value is an integer, with a default-kind int. A value such as 0.6302 never becomes an integer in binary arithmetic; past 2³¹ the conversion overflows and the loop never ends, inside the very first output. The generator therefore writes these three intervals as dyadic rationals with an exact decimal expansion (engine_interval, change below 0.4 %) and logs the rounding. For a hand-written input, choose intervals such as 0.5, 0.25, 0.125, 0.0625 or any other m/2ᵏ with k ≤ 9, written out in full (exactly ten decimals trip a second defect of the same routine, an invalid I1 format, which ends the run with a runtime error at the next output); engine_interval(x) gives the nearest such value.

Simulation segfaults immediately

Fortran code requires a large stack. The launch script sets ulimit -s unlimited; if running manually, set this in your shell first.

"N + NBIN0 … does not fit the engine build"

The engine's arrays have compile-time sizes, written into include/params.h by the --with-par preset of build.configure_flags: NMAX bodies, KMAX regularised pairs, neighbour lists of LMAX entries. Before a launch the package reads the three numbers from the configured tree and applies the engine's own start-up conditions to the input: N + NBIN0 < NMAX − 2, NBIN0 < KMAX − 2 and NNBOPT ≤ min(N/2, LMAX − 50). An input that fails one is refused with the quantity and the limit, before anything is written to the run directory. Choose a larger preset (./configure --help in the engine tree lists them; b1m holds 1 572 864 bodies and 524 288 pairs) and rebuild with install.enabled = true, or lower NNBOPT. The limits of a build are recorded as engine_limits in BUILD_INFO.toml, with MMAX, the size of the merger table of stable hierarchies (2048 in the b presets, 1024 otherwise), which the capacity section of the validity record compares with the run.

Simulation exits with status 2 after a burst of escapers

err1000 ends with Fortran runtime error: Expected REAL for item ... in formatted transfer at escape.F. The engine's escaper summary writes the names of the escapers of one adjustment interval with a format that holds a thousand of them, and the 1001st name restarts the format at a real-number descriptor. This happens in isolated multi-cluster runs, where the escape radius is 2 × 10 RSCALE about the global density centre and ejecta from an early collapse cross it together many crossing times later. The build corrects the format (Source amendments), so the failure means the binary predates that step or the amendment did not fit the engine revision: check source_amendments in the [build] table of RUN_INFO.toml and rebuild with install.enabled = true. The output written before the failure is intact.

"CUDA not found" during build

Set cuda_path explicitly in [build], or export one of CUDA_HOME, CUDA_PATH, CUDA_ROOT.

"nvcc fatal: Unsupported gpu architecture 'compute_120'"

The toolkit predates the device: consumer Blackwell (sm_120) needs CUDA 12.8 or later, Hopper (sm_90) CUDA 11.8 or later. Install a current toolkit and point cuda_path at it, or drop the architecture from cuda_arch.

"no kernel image is available for execution on the device"

The binary carries native code for other architectures and no PTX the driver can compile for this one. Rebuild with cuda_arch empty (the visible device's capability is detected) or including the device's sm_<major><minor>; a binary shared between machines lists all of their architectures.

GPU build runs, but RUN_INFO.toml shows no run.gpu_devices

The engine used the CPU path: the launcher picked a binary without the .gpu suffix (check build.binary in the run summary and enable_gpu in the config), or the GPU library found no device (GPU_LIST names an index that does not exist, or the driver is not loaded — compare hardware.gpu).

Post-processing finds no files

Check simulation.runs_dir and, for external data, postprocess.data_dir. For a specific run:

results = postprocess(cfg; run_dir = "runs/run_20260325_143022_a1f3")
generate_plots(results, cfg; run_dir = "runs/run_20260325_143022_a1f3")

HDF5 snapshots present but nothing is read

Expected: the KZ(46) H5Part layout is not supported (see the note in Configuration Reference). Enable conf.3 output in the .inp file (KZ(3) ≥ 1) and use snapshot_format = "conf3".
